## §0 一句话结论

**落地链以 CLI 位置决定槽位语义，却从不校验臂的配置指纹** —— 我用全仓 grep 证明了这个缺口
（`_land_m9_m10.py` / `_m10_dd_axis_verdict.py` 对 `config_full.json` 命中 **0 次**），
并指出它会导致**一类特定的伪裁决**：把 O-11 的**组合臂**（`dd_flat=0.10` **且** `profit_lock=1/2/3`）
当作 M10 的 DD 轴臂 `--arm10` 传入 ⇒ 引擎会把 **L2 的增益归因给 dd_flat 旋钮**。
本工具把这个缺口变成**机检门控**（8 项检查 / 4 类返回码），并在**真实臂**上验证：
真实 df 配对 **rc=0**、真实误用反例被 **G3+G4 双命中 rc=5**、M11 窗口偏移仅 **[WARN] rc=0**。

## §2 设计（只读 · 零口径漂移 · 判据零复制）

**三条纪律**（承接 O-14 / O-18 / O-20 / O-21）：

1. **只读**：不写任何文件（自检干跑落 `E:/tmp/gate_selftest/`）；**不改任何既有引擎**
   （其自检与「与已公布数字逐字一致」的结论依赖逐字输出）。
2. **零口径漂移**：`dd_flat` 复用 `_o7_long_window_tables_v2.load_dd_flat()`；
   窗口复用 `_wave5_arm_verdict.read_window()`；并附**跨实现一致性断言**（自检 T15）。
3. **判据零复制**：本工具**不重算任何策略指标**（Calmar / Sharpe / MaxDD 一律由既有引擎产出），
   只校验「配置指纹 / 产物完整性」—— **不产出任何臂级裁决**。

**★ G6 的关键修正（本轮实证得出）**：`engine.py:1210` 用
`shutil.copy2(source_file, out/'config.yaml')` 落盘 ⇒ **保留源配置 mtime**。
若按 mtime 一概判残留，**每一条真实臂都会误报**（实测：`R2A-*_df` 臂的 `config.yaml`
mtime = `09-11 03:06:10`，而运行起点 = `09-12 12:04:50`）。
⇒ 处置 = 按名排除 `config.yaml`（`MTIME_UNRELIABLE`），并在输出中**显式披露被排除项**。

### §3.1 首跑拦截记录（诚实留痕）

**首跑 12/16 ⇒ 4 项 FAIL**，定性 = **实现错 1 + 桩错 2**（+1 项随实现错连带）：

  而非「按名称命中」⇒ 断言过脆。已改为按 `name` 断言。

**第二轮（G6 修正后）**：19/19 PASS。
**教训**：①「候选键 ≠ 嵌套路径」是易犯的 API 语义混淆；②断言应锚定**语义标识**（检查名）
而非**聚合计数**（总数），否则新增检查项会连带打破既有用例。

## §5 诚实边界（强制披露）

1. **不产生任何臂级结论**：本工具只校验配置指纹与产物完整性；M9/M10 的 Calmar / Sharpe /
   MaxDD / `(A,B)` 矩阵 / FT-1·FT-2 **一律由既有引擎产出**，本工具**判据零复制**、**不改任何门槛**。
2. **联调用的是窗口2 已完成 df 臂**（非 E6 长窗臂、非 DD 轴臂）⇒ 仅证明
   **接口 / 门控 / 解析 / 渲染 / 残留检测**行为，**不构成 M9/M10/M11 的读数**。
3. **G6 的 mtime 判据有已知局限**：只能识别「结果类文件」的时间倒挂；
   若旧产物被**同秒覆盖**或**手工触碰 mtime**，则检测失效 ⇒ 需与 `G6b`（provenance 起点）
   及「输出目录全新」预检（O-15 §预检）叠加使用，**不单独作为充分证据**。
4. **G4 的跨轴守卫是「差异即报」**：M10 槽位臂与控制臂的 `staged_exit` 指纹**必须完全相同**；
   若未来出现**合法**的「DD 轴 + 其他改进」组合臂，**不得**直接塞进 `--arm10`，
   而应作为**独立轴/组合轴**登记预注册（D-112 的框架已覆盖该情形）。
5. **不追溯改判** M6~M9；**不编辑**任何既有引擎与既有报告。
