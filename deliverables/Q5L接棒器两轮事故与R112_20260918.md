## 一、第一轮事故（09-18 02:04）：多方并发起臂

### 现象
- `results/SmallAlpha191Test3_Q5L_L2_tailcut_long_o3_20260917/`（**空目录**）+ `_q5l_L2_tailcut.log`（624B，仅 banner）于 **02:04** 出现；
- 但**接棒器日志中完全没有启动 L2 的记录** ⇒ 存在**第二个执行者**（每小时自动化）。

### 根因
**自动化与接棒器并发操作同一批次** ⇒ 两侧各自起臂/清进程，互相干扰。

### 处置
1. **收权**：自动化 prompt 改为「**只读监控 + 分析 + 裁决 + 通知**」；**严禁**直接起臂/重启臂；启动器死了**只重启启动器**。
2. 游离残留归档至 `_backup/_Q5L_stray_20260918_021024/`（按纪律移动不删除）。

## 二、第二轮事故（09-18 02:12~02:22）：`Popen.poll()` 误判 ⇒ 重复起臂

### 现象（10 分钟心跳回报）
| 时刻 | 接棒器日志 |
|---|---|
| 02:12:21 | `▶ 启动 L1_split60 (pid=16596)` ｜ 活跃臂 0→1 |
| 02:17:21 | `⚠ L1_split60 已退出且无 report.json（第 1 次）⇒ 退回待启动队列` |
| 02:17:21 | `▶ 启动 L2_tailcut (pid=23436)` ｜ 活跃臂 1→2 |
| 02:22:21 | `⚠ L2_tailcut 已退出且无 report.json（第 1 次）⇒ 退回待启动队列` |
| 02:22:21 | `▶ 启动 L3_slladder (pid=11540)` ｜ 活跃臂 2→3 |

**同时**：`results/…Q5L_L1_split60…/backtest.log` = **97,605B、龄 0 分钟** ⇒ **L1 一直在正常跑**。

⇒ 接棒器**每 5 分钟起一个新臂**，并认为前面所有臂「已退出」。**若不拦截，将持续重复起臂直至并发失控**（正是用户明令避免的）。

### 根因（`_q5l_launch.py:156`）
```python
for n, pr in list(launched.items()):
    if pr.poll() is not None:          # ★致命
```
Windows 上 `run_backtest.py` **会派生子进程**（每臂 ≈2 python 进程）⇒ **父句柄很快失效** ⇒ 每轮 `POLL_S=300s` 都判「已退出」。
**与历史教训「`.start` 的 PID 是中间层进程、不可用于判存活」同源。**

### 处置
**紧急停接棒器**（防继续起臂）。代价：**L1/L2/L3 全部随之死亡**（实测 `still_l1=still_l2=still_l3=0`、FreeMB 9370→20561）。
⇒ **同时否证了 v2.2 的假设**：只加 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` **不足以**让臂脱离作业对象。

### 修复（v2.3，四处）

| # | 修复 | 说明 |
|---|---|---|
| ① | **`arm_state(nm, started_at)` 三态判定**替代 `poll()` | `report.json` ⇒ `done`；`backtest.log` mtime 龄 <300s ⇒ `running`；启动未超 `GRACE_S=900` 且无产物 ⇒ `running`（冷启动宽限）；否则 `dead` |
| ② | **死亡须连续 2 轮确认**（`dead_streak`） | 遵 **R-108**「单证据不下死亡结论」 |
| ③ | **`BREAKAWAY = 0x01000000`（CREATE_BREAKAWAY_FROM_JOB）** | 叠加在 `DETACHED` 上，带 `OSError` 回退（作业不允许则退回 DETACHED）；日志打印实际生效 flags |
| ④ | 记录 `started_at` / `dead_streak` 状态字典 | 支撑 ①② |

**自证（造反例）**：**5/5 PASS**

| 造的例 | 期望 | 实得 |
|---|---|---|
| 含 `report.json` | `done` | `done` ✅ |
| 新鲜 `backtest.log` | `running` | `running` ✅ |
| 陈旧 `backtest.log`（mtime −9999s） | `dead` | `dead` ✅ |
| 无产物 + 刚启动（`started_at=now`） | `running`（宽限） | `running` ✅ |
| 无产物 + 启动 >GRACE（`now−9999`） | `dead` | `dead` ✅ |

`py_compile` OK；备份 `_backup/_q5l_launch.py.bak_pollfix_20260918_022452`。

## 三、★R-112（新规，强制）

> **Windows 上禁止用 `Popen.poll()` 或 PID 名单判定子进程存活。**
> 凡「存活 / 死亡」判定，**一律使用产物信号**：`backtest.log` 的 mtime 龄 + `report.json` 是否存在。
> 附加**运维纪律**：**停启动器 ≡ 终止整批**（在 `CREATE_BREAKAWAY_FROM_JOB` 实测生效前）⇒ **不得为「防止启动器乱起臂」而频繁停它，正确做法是先修判据再启。**

**同族清单（R-108 家族累计 8 例，本条为第 8 例）**：
8. `Popen.poll()` 判 Windows 子进程存活 ⇒ **假阴性/假阳性混合**，每 5 分钟误判一次（2026-09-18）。
