## 二、三项实质缺陷（全部经实证）

### ★★★ P0-1（致命·集成层）：`use_daily_scale=true` 使整个回撤机制族**永不执行**

**证据（`test_garch_position_audit.py` T1，源码契约）**：

```
strategy.py:3742   if self._garch_cfg.get('use_daily_scale', False):
strategy.py:3743-3747   total_exposure = _daily_vol_scale ... ;  ret_matrix = None   ← ★
strategy.py:3766   if ret_matrix is not None and ret_matrix.shape[1] >= 3:
strategy.py:3767       garch_scale, annual_vol, info = self._garch_ctrl.compute(...)  ← ★
```

`compute()` 是**四级回撤阶梯、恢复缓冲、kill-switch 三者唯一的执行入口**（均在其中）。
而生产配置 **`use_daily_scale: true`** ⇒ 走日频分支 ⇒ `ret_matrix = None` ⇒ 守卫 `ret_matrix is not None` 不成立 ⇒ **`compute()` 从不被调用**。

⇒ **后果：若 Q3 只把 `use_drawdown_control` 改成 `true` 而保留 `use_daily_scale: true`，四级回撤阶梯的启用效果为「零」——纯粹的无用功，且会浪费一整批长窗机时（约 12h/臂）。**

**这是本次审计的最高价值发现。**

### ★★ P0-2（功能缺陷·已修复）：恢复缓冲实际只生效 1 期，且状态冻结

**修复前实证（T4.3 / T4.4 / T4.5 三项 FAIL）**：

```python
# 修复前 line 350
if self.use_recovery_buffer and was_in_hard_floor and now_recovering:
```
`was_in_hard_floor = (_last_dd >= 0.15)`。过渡**首期**该式为真，缓冲启动；但首期结束时 `_last_dd` 被更新为 <15% ⇒ **次期起条件恒为假 ⇒ 缓冲中断**。

实测（`recovery_buffer_periods=3`，NAV 序列 100→82→90→94→96）：

| 期 | DD | `buffer_active`（期望/实测） | `_buffer_remaining` |
|---|---|---|---|
| 2 | 18% | False / False ✅ | 0 |
| 3 | 10% | True / **True** | 3→2 |
| 4 | 6% | True / **False ❌** | **2（冻结）** |
| 5 | 4% | True / **False ❌** | **2（冻结）** |

⇒ 双重后果：①「跨 3 期渐进恢复」的设计意图**未实现**；②`_buffer_remaining` **冻结在 2**，造成状态污染（后续恢复不再受缓冲约束，且数值不可预期）。

**附加缺陷（同段）**：
- `_buffer_from = self._last_scale` —— `_last_scale` 是 **final_scale**（已含 `vol_scale` 与 `min_scale` 夹取），而缓冲混合的目标是 **dd_scale**。语义偏移：当 `vol_scale < 地板值` 时起点被错误压低。
- 原 `line 367` `dd_scale = min(dd_scale, self._buffer_from + (dd_scale - self._buffer_from))` 为**恒等死代码**（注释声称 "ensure monotonic"，实际未做任何钳制）。

**修复（已执行，`garch_position.py`）**：
1. 触发条件改为「**过渡首期触发 + 计数驱动直至耗尽**」，`_buffer_remaining > 0` 时继续生效；
2. 新增分支：**DD 重新升回硬地板区（≥15%）时取消未完成的缓冲**，避免与阶梯保护互相干扰；
3. 起点改用新增状态 `self._last_dd_scale`（上一期 dd_scale），修正语义；
4. 移除恒等死代码，改为明确的线性混合不变量注释。

**修复后**：`test_garch_position_audit.py` **PASS 27 / FAIL 0**；T4.3/4.4/4.5 全 PASS，`_buffer_remaining` 正确归 0。
