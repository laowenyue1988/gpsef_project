### 7.2 我自己的启动器有一处**存活检测假阴性**（已定位，未修改在跑脚本）

`_s15_shard_launch.sh` 与 `_queue_s17.sh` 均用

```bash
ps -W 2>/dev/null | grep -c "rebuild_all_barra"
```

统计存活分片数 ⇒ **恒为 0**（假阴性）。原因：**Windows 的 `ps -W` 只输出可执行文件路径，不含命令行参数**，故 grep 关键字永远匹配不到。
（正确做法：用 `Get-CimInstance Win32_Process` 读 `CommandLine`，或让分片写 sentinel 文件 / 由启动器用 `kill -0` 检查自身子进程。）

**影响评估（重要）**：
- `_s15_shard_launch.sh` 的巡检循环用的是 **`kill -0 "$p"`（自身子进程 PID）** ⇒ **判定正确**，仅显示层面受影响；
- `_queue_s17.sh` 的门禁条件是 `n >= 518 AND alive == 0`；因 `alive` 恒为 0，实际等价于 **`n >= 518`** ⇒ **门禁仍然是安全且更严格的**（BARRA 覆盖度才是真正需要满足的条件）⇒ **无实质风险**。
- ⇒ **处置：不修改正在运行的脚本**（常青纪律：禁止编辑在跑脚本；bash 逐行读取脚本，改动会破坏执行）。**待 S17 结束后**再把存活检测改为正确实现，并作为 **R-108 同族案例**（"工具自证不足 ⇒ 假读数"）登记。
