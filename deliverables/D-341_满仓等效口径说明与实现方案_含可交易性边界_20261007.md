# D-341 · 「满仓等效」口径说明与实现方案（含可交易性边界）

> **日期**：2026-10-07｜**性质**：**零算力**（纯口径澄清 ＋ 配置走查；未起臂、未改生产码；代际仍 **G18**）
> **触发**：用户质询 ——「原策略仓位是由中间的止盈止损决定的，怎么能做到满仓等效？若要实现，策略该怎么改？」
> **编号**：`D-341`（按用户授权由代理分配，可撤销）
> **用途**：**对外答疑用**。团队若质疑「你们说满仓等效回撤 34.70%，可你们根本没满仓过」——本档即标准答复。

---

## §0 一句话答复（可直接对外引用）

> **「满仓等效」不是一个交易动作，而是一个"换算尺子"（度量口径）。**
> 它把**已经发生的每日收益**乘以一个**常数** `k = 1 / 平均敞口 = 2.336189`，再重算年化/波动/回撤 —— 目的是**剔除"仓位轻"这个混淆项**，让不同仓位轻重的策略能公平比较。
> **它不是"策略跑到了满仓"，也不是"建议加杠杆"。** 若真要把它变成可交易的策略，需要**改三处机制**（见 §3），而且**会破坏 IC 门控这一已被验证有效的机制**，并且**回撤会直接撞破 20% 门槛** ⇒ 本项目**不建议实现**，只作为**风险标尺**并列披露。

---

## §1 为什么会有人问这个问题 —— 先把敞口 42.80% 的来源讲清楚

采纳包的**仓位不是"设定"出来的，而是"漏"出来的**。三个机制叠加：

| # | 机制 | 配置事实（`Q5R_OPT_dump_full_20260923/config_full.json`） | 对敞口的作用 |
|---|---|---|---|
| **1** | **分批止盈/止损减仓** | `staged_exit.enabled=True`；四档卖出比例 `sell_pct = 0.25 / 0.35 / 0.20 / 0.20`（合计 1.00）；止损 `sl_sigma = −1.8 / −1.8 / −2.4 / −2.4`；止盈 `pt_sigma = 4.5 / 4.5 / 6.0 / 9.0`；`hard_sl_sigma = −6.0` | 触发一次卖一批 ⇒ **持仓被逐步清空** |
| **2** | **★出场后资金不再投入** | `staged_exit.reinvest_enabled = False`（`reinvest_min_amount = 5000` 因此不生效） | 卖出后的钱**趴在现金里**，直到下次调仓 |
| **3** | **调仓频率低** | `rebalance_interval = 20`（交易日） | 中间最多 **20 个交易日**不回补 ⇒ **敞口单调下滑** |
| **4** | **IC 门控压建仓规模** | `meta_labeling.auc_gate_enabled = True`；`ic_gate_threshold = 0.02` | 信号弱时**主动降低总仓位** ⇒ 敞口呈**双峰**（`<20%` 占 **34.1%**、`>80%` 占 **17.6%**） |

⇒ **平均敞口 42.8048% 是这四条的联合结果**，其中**第 2 条（出场不再投）**贡献最大。
⇒ 但**这不影响"满仓等效"的成立** —— 因为它压根不依赖仓位是"设定"的还是"漏"的：**只要知道每日实际收益和平均敞口，就能做换算。**

## §2 ★「满仓等效」的精确定义（三条边界，务必整段同引）

### 2.1 定义（R-171）

```
满仓等效日收益：  r'_t = r_t × k ,   其中 k = 1 / 平均敞口 = 1 / 0.428048 = 2.336189
然后对 {r'_t} 重算 年化 / 波动 / ★Sharpe / |MaxDD|
```

锚实测：原样 \|MaxDD\| **16.3337%** ／均敞口 **42.8048%** ⇒ **满仓等效 \|MaxDD\| 34.6984%**。

### 2.2 三条边界（**违反任一条即为误用**）

| 边界 | 内容 | 为什么 |
|---|---|---|
| **① 用常数 `k`，禁逐日归一** | **禁用** `r_t / e_t`（逐日敞口归一）后再复利 | 逐日归一会让**路径形状改变** ⇒ ★Sharpe 漂移，不再是同一把尺子（R-171 明文禁止） |
| **② 它是"假想曲线"，不是可交易策略** | 假设**零融资成本、无杠杆约束、无额外冲击成本** | 真实放大 2.34 倍会带来融资利息、强平风险、成交冲击（微盘股尤甚） |
| **③ 它不改策略的决策路径** | 门控何时降仓、哪只股票何时被止损 **全部按原样**，只是结果整体放大 | 所以它衡量的是"**同样的决策，若满仓会怎样**"，不是"改了策略会怎样" |

### 2.3 ★★最容易混淆的一组对比（本档核心）

| | **R-171 满仓等效（口径）** | **真·恒满仓（策略改造）** |
|---|---|---|
| 数学形式 | `r'_t = r_t × k`（**常数**） | `r''_t = r_t / e_t`（**逐日变动因子**） |
| 平均敞口 | 100% | 100% |
| 路径形状 | **完全保留**（所有回撤恰好 ×k） | **改变**（`<20%` 与 `>80%` 的日子被差异化放大/缩放） |
| ★Sharpe | **严格不变**（算术口径 Δ = 2.22×10⁻¹⁶，R-175 已自证） | **会变**（无理由不变） |
| 可交易性 | 不可交易（假想曲线） | 可交易（但需改造 ＋ 融资安排） |
| 用途 | **风险标尺 / 公平比较** | 一个新策略 |

> **⇒ 一句话：平均敞口可以对上，但"路径"和"指标"不是一回事。这就是为什么「满仓等效」不能理解成「策略其实跑到了满仓」。**

### 2.4 为什么必须有这个口径（不然会误读）

**★Sharpe 对敞口尺度严格不变（D-252 尺度不变性）** ⇒ **低仓位不创造 alpha，只等比压低波动与回撤**。
若不并列满仓等效，就会**用"仓位轻"冒充"风险低"** —— 这正是 Q5E 验收条款要求双口径并列的原因。

## §3 如果真要实现（可交易的满仓版）—— 改造清单

**必须先明确目标**，两种目标改造量完全不同：

### 目标 A：只把「平均敞口」抬到 100%，**保留**门控与出场的相对调节

| 项 | 需要改什么 |
|---|---|
| 总仓位 | 在**总仓位目标**上乘常数 `k = 2.336`（保留日内相对结构） |
| 杠杆 | **不需要杠杆**（敞口上限 100% ≤ 无杠杆上限 100%）；若要 `>100%` 才需融资 |
| 成本 | 需新增**融资成本项**（仅在 >100% 时） |
| 结论 | ★**结果 ≠ R-171 满仓等效**（路径不同）⇒ **不可用目标 A 去"实现"口径值** |

### 目标 B：真正做到「每日恒满仓」—— **必须改三处**

| # | 改造点 | 当前值 | 改成 | 副作用 |
|---|---|---|---|---|
| **①** | 出场后立刻再投 | `staged_exit.reinvest_enabled = False` | **`True`**（并适配 `reinvest_min_amount`） | 交易频次与成本上升；**改变了成交路径 ⇒ 改标签 ⇒ 按 R-163/R-198「replay 失效、训练侧端点失格」** |
| **②** | 建仓规模归一到"用尽可用资金" | 现有 `max_positions=20` × `max_position_pct=0.1` ⇒ 名义上限 200% | 每轮把可用现金**全部**按权重投出，敞口恒 ≈100% | 单只权重被摊薄/集中度变化 |
| **③** | 处理 **IC 门控的减仓分支** | `auc_gate_enabled=True`、`ic_gate_threshold=0.02` ⇒ 弱信号时降仓 | 关闭减仓分支（只保留选股过滤） | ★**等于废掉 IC 门控机制**（而该机制是敞口双峰与回撤控制的来源之一，见 D-246/D-300 §3-H） |

### ★目标 B 的三条硬性警告

1. **它不再是同一个策略** ⇒ 必须走**完整新实验流程**（预注册 ＋ 长窗回测 **≈13.7h/臂** ＋ R-162 门槛 ①同代际②单变量③Δ★Sharpe ≥ 0.2482 ∧ Δ★Calmar ≥ 0.2824④单调⑤关闭出口）。
2. **回撤会直接撞破 Q5E 的 20% 门槛**：满仓等效 \|MaxDD\| 已是 **34.70%**；恒满仓的真实回撤将在**同一量级**（30%+）⇒ **与 `|MaxDD| < 20%` 验收线直接冲突**。
3. **微盘股流动性约束**：敞口从 42.8% 提到 100% ⇒ 成交量放大约 **2.34 倍**；微盘股冲击成本**非线性上升**（原回测 `slippage = 0.001` 是固定假设，放量后不成立）⇒ **实际收益会低于线性外推**。

### 目标 C（**本项目建议**）：**不实现，只作口径**

| 理由 | 说明 |
|---|---|
| ① | 本项目**全部结论都不需要它落地**（9 条轴 inconclusive / 3 条负效应 / 0 条达门槛 ⇒ 维持现行配置） |
| ② | 恒满仓会**废掉 IC 门控**，而门控是现有回撤结构的一部分 |
| ③ | 融资成本 ＋ 强平风险 ＋ 微盘冲击，三者都未被现有框架建模 |
| ④ | **正确用法** = **两种口径并列披露**：原样 \|MaxDD\| **16.33%** ＋ **满仓等效 34.70%** ＋ **均敞口 42.80%**，并注明「**满仓等效为度量口径，非可交易策略**」 |

## §4 对外答疑标准话术（三段，可直接照读）

> **① 定义**：「满仓等效」是把每日收益乘一个常数（1 ÷ 平均仓位 = 2.34），再重算回撤和夏普。它回答的是"**如果同样这套买卖决定、但仓位一直是满的，风险会多大**"。
>
> **② 为什么必须给**：因为夏普对仓位轻重严格不变 —— 仓位轻只会等比压低收益和回撤，**不会创造能力**。只报 16.33% 会让人误以为风险低，所以必须同时给 34.70%。
>
> **③ 它不是交易建议**：它假设零融资成本、无杠杆约束、无额外冲击成本；我们**没有**、也**不建议**把仓位真的拉到满仓 —— 那需要改三处机制、会废掉 IC 门控、回撤会直接超过 20% 门槛，而且微盘股放量 2.34 倍后冲击成本会显著恶化。**它只是标尺，不是路线图。**

## §6 小白版（四问）

**① 这段在解决什么问题？**
团队会问：**「你们的仓位明明是中途止盈止损一点点卖掉的，怎么可能'满仓'？这个 34.70% 是不是编的？」** 这段就是回答这个质疑。

**② 用了什么办法？**
把策略每天的真实收益，**乘一个固定倍数 2.34**（＝1 ÷ 平均仓位 42.8%），然后重新算一遍回撤和夏普。**不改变任何买卖决定**，只是把结果按比例放大 —— 就像把一张地图整体放大 2.34 倍，形状不变，只是尺寸变了。

**③ 结果是什么？**
- 原来的最大回撤是 **16.33%**，放大后是 **34.70%**；
- **夏普一模一样**（1.0396，差异只有 10⁻¹⁶ 量级）—— 因为整体放大不改变"性价比"；
- ⇒ **仓位轻只让数字变好看，没让策略更聪明。**

**④ 对你意味着什么？**
- **可以放心对外说**：满仓等效**是标尺，不是路线图**。我们**没有**满仓，也**不建议**满仓。
- **如果团队追问"那要实现要怎么改"**：需要改三处 —— ①出场后立刻把资金投回去（现在 `reinvest_enabled=False`）②每轮把现金用尽 ③关掉 IC 门控的减仓分支。**但第③条等于废掉一个已被验证有效的机制**，而且回撤会直接超过 20% 门槛、微盘股放量 2.34 倍后冲击成本会恶化 ⇒ **所以只把它当尺子用。**
- **需要拒绝的是什么**：「把回撤 16.33% 当成真实风险」这个说法要拒绝；「用满仓等效 34.70% 去论证策略不行」也要拒绝 —— 它两个方向都不是结论，只是**同一份数据的另一种刻度**。
