## 二、教训（4 条，全部已机制化）

1. **改训练链路（标签构造/目标变换/样本加权/特征面板列）前，必须用"覆盖已知缺陷区间"的短窗真回测跑通**，
   核验四条硬指标：`ERROR=0`、`训练失败=0`、出现 `meta_IC`、`调仓>0`。
   ⚠️ **烟测窗若避开缺陷区间，等于没测**（R-126 的 2021 年烟测就是这样放过了这个 bug）→ **R-127**。
2. **绝不可以在臂运行时改共用源码**；需要改就必须等静默窗。→ **`guard-edit` 闸门（强制）**。
3. **`report.json` 存在 ≠ 读数有效**。落臂后**必须先过有效性审计**（中途改码 + 四类错误计数 + 零持仓 + 有调仓）
   才能读数、才能进判据。→ **`audit` 闸门（强制）**。
4. **判活必须含"起臂后初始化宽限"**：数据加载期 5~10 分钟内没有任何产物，
   纯产物信号判活会把在跑臂判死（我因此实发**重复起臂 6 次 / 14 个进程 / 同一目录并发写**）→ **R-129**。

## 三、实验版本管理机制（工具 `_exp_version.py`）

| 子命令 | 何时用 | 作用 | 拒绝条件 |
|---|---|---|---|
| `freeze --note` | 一批实验开始前 | 冻结「代码 + 配置」指纹基线（`_exp_frozen.json`） | — |
| `status` | 任何时刻 | 对比当前代码与冻结基线的**漂移** | — |
| **`preflight`** | **每次起臂前** | ①登记本臂指纹+配置 md5 ②校验与冻结基线一致 ③**若已有臂在跑且源码 mtime 晚于该臂起臂时刻 ⇒ 拒绝** | 版本漂移未声明 / 在跑臂期间改过码 |
| **`guard-edit`** | **改源码前** | 有臂在跑就拒绝 | 存在在跑臂 |
| **`audit`** | **落臂后 / 读数前** | 三重判据：①`provenance` 中途改码 ②R-127 四类错误计数 ③零持仓轮 / 必须有调仓 ⇒ 判 `VALID / INVALID / INCOMPLETE / RUNNING` | 任一不过 ⇒ **INVALID，禁止进判据** |

**登记表**：`_exp_registry.json`（机器）+ `deliverables/EXPERIMENTS.md`（人读，自动生成）。

### 已验证的判别力（不是"声称"，是实测）
- **事故复现**：`audit --only CONTAMINATED` 对 N1 归档件输出
  `❌ INVALID … 运行期源码被改写：declared=[…strategy.py] md5diff=[…strategy.py]；ERROR=56；元标注模型训练失败=28；内…` ⇒ **两个根因同时被抓出**。
- **无误伤**：在跑中的臂标 `⏳ RUNNING`（不因"尚未调仓"被误判）；N2 归档件标 `⚠️ INCOMPLETE`（未落臂）。
- **闸门实测**：当前有臂在跑时 `_apply_q5n_patch.py --restore-only` **被拒绝**；`--dry` 正常；源码 md5 未变。
- **自测**：`selftest` 6/6（1 正常 + 5 反例，含内层越界与零持仓）。

### 接线（强制路径）
```
起臂前:  _exp_version.py preflight --tag T --config C --purpose ... --hypothesis ...
改源码:  _exp_version.py guard-edit --why "..."        ← _apply_q5n_patch.py 已内置调用
落臂后:  _exp_version.py audit                          ← 监督器 verify/verdict 阶段已内置调用
                                        ⇒ 审计不过 ⇒ 不起长窗臂 / 不出判据
```
