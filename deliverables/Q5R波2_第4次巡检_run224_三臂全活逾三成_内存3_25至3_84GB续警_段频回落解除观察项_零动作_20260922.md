# ⑤小白版四问（D-269）

## 问 1：这段在解决什么问题？

我们要回答一个很根本的问题：**这个策略里那套 191 个因子 + XGBoost 机器学习模型，到底有没有真本事？** 具体做法是做一个"**零信息对照实验**"——把模型的预测值和股票**随机打乱**（术语叫 `preds_mode=random`，即随机置换），然后照常跑完整回测。这样模型就"完全瞎猜"了。如果瞎猜的成绩和真模型差不多，说明模型没用；如果真模型明显更好，说明它有价值。

现在正在跑的是**第 2 批（波 2）**，3 个臂（R3/R4/R5），用**不同的随机种子** 3/4/5。上一批（波 1）只跑了 3 个臂，用户和我们都认为"3 个样本太少，结论不足以下判"，所以这一批是**按预注册设计补样本**，跑完就有 6 个随机臂可以比较了。

## 问 2：用了什么办法？

- **看护方式**：完全只读。读三臂的 `backtest.log`（回测日志）看进度、看有没有报错；用 `stat` 看日志最后写入时间判断进程是否还活着（术语叫 **R-125 判活**：日志龄 <300 秒 = 活；>1800 秒且 python 进程数 = 0 = 疑似真死）。
- **算完成时间（ETA）**：术语叫 **R-143 口径** —— **不能用文件修改时间、也不能用刚起跑时的快照**，必须用**日志里自带的时间戳**、取**连续多段的稳定速度**再外推。本轮各取末 11 段。
- **内存检测**：用 Windows 的 `GlobalMemoryStatusEx` 接口（通过 Python `ctypes` 调用）连续采样 **24 次**（约 30 秒），因为单点采样会骗人（历史上多次出现"单点值恰好在临界线上"的误判）。
- **有效性闸（R-V1）**：检查日志里是否真的出现了 `preds_mode=random` 字样、随机种子是否每个臂纯净且互不相同、每次是否覆盖全部 300 只股票、置换日期是否一天一次不多不少。
- **故障监控（R-127）**：检查八类致命错误（`ERROR`、缺少必需列、模型训练失败、数组越界、输入被意外修改、异常堆栈、标签生成异常、连续空持仓）。
