## ② 本小时深度分析：★amount/vwap 影响面——新增"因子活跃度"独立证据

### 2.0 背景（一段话）

主代理于 14:07~14:08 完成《因子快照 amount/vwap 复权方向 · 独立二次复核》（v2 终版），结论 = **缺陷属实**（`local_provider.py:263` 把 `amount` 乘 `1/f`，而 OHLC 乘 `f`，方向相反；三重证据钉死：代码逐字三版本一致 / 相对误差 0~2.21e-16 机器精度 / 经济不变量 `low≤vwap≤high` 由 raw 0 越界 → 现状 16~252/266 越界 → 修复后 0）；**四个备选解释全部排除**（含"日线 ×1/f 与分钟 ×1 自相矛盾"的决定性旁证）。**但"前期实验全部失败"不成立**：当日快照值 300/300 逐位一致、训练/预测自洽（非前视非 train-serve skew）、影响为 **39/190 列 × 按 lookback 2~86%（短窗 2~4%）** 的有界扰动。

**该档仍留一个未测环节**：§4.1 第 ④ 条明言「**尚无"决策改变"的证据**——"因子列变化 ⇒ 模型决策变化 ⇒ 绩效变化"这条链每一步都需要测量，目前一步都没测」。

**本巡检的独立贡献 = 对这条链补上第一个可测环节**（零算力、只读）：**这 39 个受影响因子，在模型里究竟是"休眠列"还是"活跃列"？**

### 2.1 方法（只用臂自身产出的日志，不重算、不改码）

- **数据源**：波 1 三臂 + 波 2 三臂的 `backtest.log` 中 **MDA-OOS**（Mean Decrease Accuracy，置换重要性法）逐 fold 输出。
- **锚定字段**（R-139 同族纪律）：只抓 `Top-5 MDA:` / `Bottom-5 MDA:` 行中的 `alpha_\d{3}` 业务字段，**禁抓行首时间戳**。
- **受影响集**：v2 档 §3.3 明列的 **35 个 VWAP 类 + 4 个 AMOUNT 类 = 39 个**。

### 2.2 结果

| 核验项 | 结果 |
|---|---|
| 39 个受影响因子在快照 `factors_*.parquet` 中的命中 | **39/39（100%）** ｜ 快照 `alpha_*` 列共 **190** 个 ⇒ 占比 **20.5%**（**复现 v2 档数字，逐位一致**） |
| 39 个受影响因子当日取值非退化（stdev > 1e-12） | **39/39**（无退化常数、无全 NaN） |
| **★出现在 `Top-5 MDA` 的受影响因子** | **14 个 / 39 = 35.9%**（17, 26, 39, 41, 45, 61, 70, 73, 95, 125, 130, 138, 144, 156） |
| **★出现在 `Bottom-5 MDA` 的受影响因子** | **29 个 / 39 = 74.4%** |
| **★出现在任一侧极值榜（Top ∪ Bottom）** | **30 个 / 39 = 76.9%** |
| 受影响集内 Top ∩ Bottom | **13 个** ⇒ 分布**两极化**（既被识别为"有用"也被识别为"有害"） |

**旁证（全会话级）**：`[MDA-OOS] 阈值分布: MDA>0=44, MDA>0.001=9, MDA>0.005=4, MDA>0.01=2 | t 检验通过(>1.729)=41 | MDA<0=50, MDA==0=45`（n=139 入选特征）⇒ **模型确实在做逐因子重要性判别，且判别结果被用作特征筛选依据**（`RankIC≥0.001 通过: 144个特征`）。

### 2.3 判读（★这一节的结论要改一个字）

| 层面 | v2 档原文 | **本巡检补充** |
|---|---|---|
| 受影响因子数 | 39/190 = 20.5% | ✅ 复现一致 |
| 影响频率 | 短窗 2~4% 样本日 | （未复核，属 v2 档主张） |
| **因子活跃度** | **v2 档未测** | **76.9% 的受影响因子在模型 MDA 上处于活跃极值位；35.9% 进入过 Top-5** |

**⇒ 结论修订**：v2 档说「**39 个因子的贡献被轻微稀释/扭曲**」——这个表述**方向对，但"轻微"一词缺乏支撑**。事实是：**这 39 个里有近 8 成是模型眼里"有辨识力"的活跃因子**，其中 14 个还进过 Top-5。**⇒ 伪信号被学进去的路径是"通"的**（不是被低方差/低 RankIC 筛掉的死列）。

**但必须同时钉住三条边界（否则会过度反应）**：
1. **活跃 ≠ 主导**：`Top-5 MDA` 头名 `alpha_159_neu = 0.113413`（t=55.56），而受影响因子中最高的 `alpha_041_FFD_neu = 0.004915`（t=59.27）—— **量级差 23 倍**。受影响因子整体处于**中低重要性带**。
2. **扰动有界**：单因子在单日被反向缩放的幅度是 **`f²−1`**（除权日 close/vwap 跳变 +0.9%~+7.5%），且**只在含除权事件的样本日**发生（短窗算子 2~4%）。**不是全样本偏移**。
3. **仍是概率判断**：「活跃因子 ⇒ 决策会变」这条链**第二步（决策变化）和第三步（绩效变化）依然没测**。本巡检只把**第一步钉实了**。

## ⑥ 小白版四问（D-269 强制）

### ① 这段在解决什么问题？

你有一个"微盘股选股策略"——每天从全市场市值最小的 300 只股票里挑 20 只买入。前一轮我（主代理）查出**一个数据错误**：算"成交金额"（`amount`）时，除权日的数字被乘了 `1/f`，而股价乘的是 `f`——**两个方向反了**。你担心的是："**那我前面做的所有实验是不是都白做了？**"

同时还有一个背景问题：**正在跑的实验（波 2，3 个"随机选股"对照臂）到底跑得怎么样？** 这 3 个臂是回答"**191 个因子 + XGBoost 到底有没有用**"这个根本问题的关键——它们把"预测值"和"股票"的对应关系**随机打乱**，如果打乱后业绩和真策略差不多，就说明模型其实没用。

### ② 用了什么办法？（含开关名/参数/数字）

**监控部分**：读 3 个臂的 `backtest.log`（进度行 `回测进度: 300/1315`）与心跳日志；用日志**内嵌时间戳**做连续 10 段差分算 ETA（这是 **R-143** 纪律，禁用文件修改时间）；物理内存用 Windows API `GlobalMemoryStatusEx` **连续采样 20 次**（R-144 纪律：≥10 采样 + 认单态还是双态）；提交余量 = 系统总页面文件 77.51GB 减去已用。

**分析部分（本轮新增）**：把"**受 amount/vwap 错误影响的 39 个因子**"名单，和波 1/波 2 六个臂日志里的 **`MDA-OOS`（Mean Decrease Accuracy，一种"把某个因子打乱后看模型准头掉多少"的重要性打分）** 逐条交叉比对——**看这 39 个因子在模型眼里到底是"有用"还是"摆设"**。

三个关键数字：**190**（快照里因子总列数）、**39**（受影响列数 = 20.5%）、**76.9%**（受影响因子中出现在 MDA 极值榜的比例）。

### ③ 结果是什么？

**监控结果**：
