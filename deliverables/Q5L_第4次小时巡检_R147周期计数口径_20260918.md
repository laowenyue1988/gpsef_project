## 2. ★★R-147 新登记【中】· 周期计数口径静默失效（本轮核心增量）

### 第一手事实
本轮我沿用 run128~run130 的 `目标模式=` 作为周期标记计算进度，读得 **40/39/42 of 66（60.6/59.1/63.6%）**，
**看似已过半**；但**行号级取证**显示 `目标模式=` **每周期命中 2 行**：
```
1599:  [L2] 目标模式=regression: objective=squarederror, 度量=Spearman IC, ...   ← 训练端目标声明
1659:  【嵌套 Purged K-Fold CV】K=5, embargo=21天, 目标模式=regression              ← CV 段声明
```
⇒ **`目标模式=` 计数 = 周期数 × 2** ⇒ 进度被**系统性高估 2 倍**（60.6% 实为 30.3%）。

### 正解
**唯一周期标记 = `[B1]`**（重训段起点，每周期恒定 1 行）。
**R-108 判别力自证**（本轮实跑）：
```
[B1]                    = 21   <- 真周期数
目标模式=                = 42   <- 2× 周期
嵌套 Purged K-Fold CV    = 21
ratio nTGT/nB1 = 2.000 (期望 ~2.0)  |  nB1 == nCV = True
⇒ PASS: [B1] 是正确且唯一的周期口径
```

### 影响范围（关键）
- **保护有效性不受影响**：本自动化**只做只读监测**，计数口径错误**不会**导致杀臂/误启动；
  回测本体、`_q5l_launch.py` 门控、S1~S6 判据**均不受影响**。
- **受损的是监测侧审计可信度**：ETA 外推基于错误的周期基数 ⇒ 若继续沿用会得出**过早的 ETA**。
- **与历史轮次的关系**：run128~run130 记录的 "4/4/5"、"10/9/11"、"16/15/17 of 66" 等进度读数
  **须按 ÷2 口径复核**（即 run130 的 16/15/17 实为 **8/7.5/8.5** 周期量级）；**历史 ETA 均为乐观偏差**。
  ★保留原记录不删改（**append-only 审计纪律**），本节即为更正留痕。

### 裁决
**登记【中】、本轮不修复**（跑期禁改在跑批监测代码属 R-110 精神；且修正仅需下一次巡检换标记即可）。
**否定的是路径还是机制价值**：否定的是 **`目标模式=` 这一代理变量的选择路径**（每周期非唯一），
**不是**「周期计数作进度真代理」的机制价值（该机制仍正确，仅需换用唯一标记 `[B1]`）。
