## 2. 信号文件协议 v3（两框架的唯一接口）

### 2.1 两类信号

**A) 调仓信号**（每个调仓日一个，文件名 = 调仓日 YYYYMMDD）：

```json
{
  "signal_date": "2022-08-01",
  "strategy": "small_alpha191_test2",
  "target_count": 20,
  "scale": 0.5,                          ← 调仓日 build_scale（回撤熔断×趋势过滤）
  "targets": [
    { "code": "sh.601279", "weight": 0.05454, "sigma": 0.033432 },
    ...
  ],
  "note": "由 gpsef R12 回测导出 (协议v3: weight+sigma+scale, 无参考价)"
}
```

**B) 除权信号**（持仓股票除权日盘后生成，文件名 = 除权日 YYYYMMDD）：

```json
{
  "type": "corporate_action",
  "code": "sh.600000",
  "ex_date": "2024-05-10",
  "stock_ratio": 0.3,        ← 送股/转增比例（0.3 = 每10股送3股）
  "cash_per_share": 0.5,     ← 每股现金分红
  "bonus_ps": 0.0            ← 每股送股（面值部分）
}
```

### 2.2 字段语义（v3 关键设计）

| 字段 | 语义 | 来源 |
|---|---|---|
| `weight` | 目标权重（等权 ≈ 1/20） | 离线选股结果 |
| `sigma` | 入场 daily vol（**离线同口径**） | 离线 `_compute_entry_vol` |
| `scale` | 调仓日 build_scale（回撤熔断×趋势过滤） | 离线调仓日状态 |
| ~~ref_price~~ | **已删除**——离线盘前无买入价，发参考价会误导 | — |

### 2.3 信号导出（gpsef 侧）

```bash
cd E:\quant\gpsef_project
.venv\Scripts\python.exe scripts/export_signals.py \
    --orders results/<回测目录>/orders.csv \
    --log results/<回测目录>/backtest.log \
    --config strategies/small_alpha191_test2/config.yaml \
    --out E:/quant/Eureka/signals
```

- σ：复现 `_compute_entry_vol`（rolling std / EWMA λ=0.94 seed=60d，参数来自 config）
- scale：从回测日志 `[方案A] 建仓规模 xS (回撤熔断=X, 趋势=Y)` 提取
- 除权信号：由离线策略在除权事件回调（`on_ex_dividend`）中生成

## 3. 三问分析与设计决策（2026-08-31 评审）

### 问题 1：σ 计算一致吗？—— 不一致 → 信号中加入 σ ✅

**取证**：
- 离线（`_compute_entry_vol`）：`rolling std（~120日）` 或 `EWMA(λ=0.94, seed=60d)`，参数来自 `meta_labeling` 段
- 实盘 v2 自估（`_estimate_vol`）：近 20 日 `std()`——**与离线不一致**

**影响**：σ 不同 → S1-S4 的 PT/SL 阈值价格不同 → 实盘止盈止损触发点与离线系统性偏离。

**决策**：信号中加入 `sigma`（离线计算入信号），实盘建 tracker 直接用，**逐位一致**。

**验证**（三重）：
1. 单元：实盘注册 σ == 信号 σ：3天 20/20、30天 39/39 ✅
2. 数值交叉：信号 σ=0.033432 vs 离线日志 PT 反推 0.033239（偏差 0.58%，为日志 2 位小数舍入）✅
3. 资金：target_value = 总资产×weight×scale 实测 ratio=1.00 ✅

### 问题 2：ref_price 不合适 → 发 weight+scale，买入价实盘开盘读 ✅

**取证**：离线建仓 `broker.order_target_percent(code, target_w * build_scale)`——资金分配 = **权重×规模因子**，**不含价格**；买入价是开盘后 `_get_open_price` 读取。

**决策**：
- 删除 `ref_price`（盘前无买入价，发参考价无意义且误导）
- 新增 `scale`（调仓日 build_scale）——由离线算好入信号（实盘无回撤熔断/趋势过滤上下文）
- 实盘：`target_value = 总资产 × weight × scale` → 开盘后读实际价 → `股数 = target_value/价` 取整

**验证**：scale=0.5 信号 → 首单 target_value=27,270 == 期望 总资产×0.0545×0.5 ✅

### 问题 3：除权怎么办？→ **v5 最终方案：实盘后复权双轨制（等比调整方案已被更优替代）** ✅

**v3 结论（有误）**：曾引用离线 `on_ex_dividend` 的"PT/SL 基于前复权价，无需调整"，得出"实盘仅同步股数即可"。

**用户质疑（正确）**：
> 离线回测可固定一个**未来的前复权基准日**，除权日复权价连续 → 阈值不动成立；
> 但**实盘没有未来基准日**，真实交易只能用真实价——除权日真实价**跳变**（如 10 元 10 送 10 → 除权参考价≈5 元），若 σ/阈值不动：
> - **止盈锁死**：PT = entry×(1+3σ) ≈ 13 元，除权后股价≈5 元**永远无法触及**
> - **立即误止损**：SL = entry×(1-3σ) ≈ 7 元，除权开盘 5 元**直接跌破**

**客观评价**：质疑**完全成立**。这是"回测语境"与"实盘语境"的本质差异——离线前复权连续性结论**不能迁移到实盘真实价体系**。

**v4 决策（完整修正）**：
- 实盘除权必须**等比调整入场基准**：`entry × price_factor`（除权参考价/除权前收盘），PT/SL 阈值**随 entry 等比缩放**——除权后触发点相对真实价的比例与除权前**逐位一致**
- `qty × (1+stock_ratio)`（送转股数增加，券商端自动）
- **σ 不动**（波动率性质不变）
- `cum_max_up/cum_max_dn × price_factor`（累计极值同步缩放，保持相对收益）
- 现金分红入账（`cash_per_share × qty`）
- 除权信号由离线导出（`ex_factor` 由离线按除权参考价精确计算）

**验证**（test_corporate_action_v4.py + 集成测试）：
1. 相对比例不变：除权前 S1-S4 PT 比例 1.090/1.090/1.120/1.270 == 除权后（entry 10→5）**逐位一致** ✅
2. 用户担忧场景：
   - 除权后价 5.2（+4%，1.33σ）→ **不触发** ✅（正常波动）
   - 除权后价 5.6（+12%，4σ）→ **正常触发 S1 止盈** ✅（止盈不再锁死）
   - 除权后价 4.6（-8%，2.7σ）→ **不触发** ✅（无误止损）
3. 集成：除权信号 → qty x1.300 + entry x0.725 + σ 不变 + 分红 2,050 入账 ✅
4. 3/30 天回归全通 ✅

**除权信号协议（v4 增强）**：
```json
{
  "type": "corporate_action",
  "code": "sh.603682",
  "ex_date": "2022-09-29",
  "stock_ratio": 0.0,
  "cash_per_share": 0.22,
  "bonus_ps": 0.0,
  "ex_factor": 0.962069      ← 除权参考价/除权前收盘 (离线精确计算)
```

### ⭐ 用户更深洞察 → v5 最终方案：实盘后复权双轨制

**用户追问**（比"除权怎么办"更根本）：
> 离线框架用价格双轨制处理除权——止盈止损信号触发由**前复权**处理，触发后真实交易用**真实价**。
> 但实盘框架下，**不存在这样的价格双轨制！因为不存在一个统一的前复权基准日！**

**客观评价**：完全正确。离线双轨制依赖"固定前复权基准日"（如 2026-08-04），这是**未来日期**，实盘不可能有。所以"前复权触发 + 真实价执行"不能直接搬到实盘。

**但存在更优解——后复权双轨制**（v5，实证）：
```
后复权价 = 真实价 × backAdjustFactor（基准 = 上市首日，固定过去，实盘天然存在!）
sh.603682 除权日(2022-09-29, 10派2.2):
  raw 收益率   = -7.93%   ← 真实价跳空（执行轨, 券商实际价）
  后复权收益率 = -4.30%   ← 连续无跳空（触发轨, = 离线前复权收益率 逐位一致!）
```

**为什么这是最优解**：
1. **基准=上市首日（过去固定）**——实盘存在，不像前复权需要未来基准日
2. **收益率与前复权逐位一致**（前复权 = 后复权/bf(基准日)，只差常数缩放，不影响收益率）→ 实盘触发点与离线回测**完全对齐**
3. **除权零处理**——后复权价除权日连续，σ 收益天然正确，**entry/σ/阈值全不动**（比 v4 事件驱动的 ex_factor 调整更干净）
4. 数据桥 `_load` 直接读 raw_daily + merge 复权因子，**不依赖 reference_date**

**v5 双轨实现**：
- **执行轨**：`open/high/low/close` = 真实价（券商成交价）
- **触发轨**：`adj_open/adj_high/adj_low/adj_close` = 真实价 × backAdjustFactor（后复权）
- 建仓：`entry_raw` = 真实价（执行），`entry_adj` = 后复权价（触发）
- 止盈止损：用后复权 bar 触发 → 触发价换算真实价下单：`raw = adj / 当日因子`
- 除权：仅 qty×送转比例 + 现金分红入账，**entry/σ/阈值全不动**

**验证**（v5 全量）：
1. 后复权除权日连续：raw -7.93% vs adj -4.30%，与离线逐位一致 ✅
2. σ 一致性：3天 20/20、30天 39/39（entry_adj=后复权, entry_raw=真实价, σ=信号σ）✅
3. scale 资金 ratio=1.00 ✅
4. 除权 v5：qty 4000→5200（×1.3），entry_adj/σ 阈值全不动 ✅
5. 3/30 天回归全通 ✅

> **架构决策**：v4 的"事件驱动 ex_factor 等比调整"仍是正确兜底（当复权因子数据缺失时）；
> v5 后复权双轨为**主方案**（数据层保证连续性，策略层零事件依赖）。

### 4.2 策略执行语义（v6 分钟级）

**数据源**（数据桥 GpsefDataCenter）：
- 日线：`data/raw_daily/*.parquet`（真实价）+ `data/back_adjust_factors/*.parquet`（后复权因子）→ 双轨：`close`=真实价（执行）、`adj_close`=后复权（触发）
- **分钟线：`data/raw_minute/5min/*.parquet`（5415 只，2022-01 起）**——盘中 5 分钟粒度精确触发
- 分红：`data/dividend_data/*.parquet`（已做 Eureka 契约列名映射）
- 信号：`signals/*.json`（gpsef 离线导出：调仓信号 + 除权信号）

**信号**（来自 gpsef 离线）：
- 调仓信号：`{code, weight, sigma, scale}`——权重/入场σ/建仓规模因子全部离线算好
- 除权信号：`{type, code, ex_date, stock_ratio, cash_per_share}`——实盘仅同步股数+分红

**驱动语义（v6，分钟级精确触发）**：
```
回测/实盘周期: 5min（Eureka 引擎 trade_in_minute 逐 bar 驱动 run_period）

每日盘前 before_market_open:
  ① 查调仓信号 → 设置 _pending_targets + _pending_scale
  ② 查除权信号 → 同步股数 + 分红入账（σ/阈值不动, 后复权双轨自动吸收）
  ③ 清空当日 bar 缓存 + 重置 tracker 增量游标

盘中每 5min run_period:
  ① 调仓日: _execute_rebalance()（每日仅一次, _done_dates 防重）
     - 卖出不在目标的持仓
     - target_value = 总资产 × weight × scale → 开盘价 → 股数取整 → 下单
     - 注册 tracker（entry_adj=后复权价, entry_raw=真实价, σ=信号σ）
  ② _check_exits(): 5min 增量检查（tracker 持久化 cum_max, 与 gpsef _check_staged_minute 同语义）
     - 读当日 5min 后复权 bar（datacenter 缓存, 跨 bar 复用）
     - 规则引擎逐 bar 检测 S1-S4 PT/SL → 触发后 adj→raw 换算真实价下单

收盘 after_market_close:
  估值 + keeper 快照
```

```
09:45:00 sh.605488 Stage1 止盈 @14.931→raw 9.868 x400
09:45:00 sh.605336 Stage1 止盈 @20.245→raw 14.617 x300
```

### 4.3 止盈止损规则引擎（staged_exit.py）

从 gpsef `StageManager/StageTracker/_check_staged_minute` 移植的**纯函数版本**：

| 阶段 | 持有期 | PT(σ) | SL(σ) | 卖出比例 |
|---|---|---|---|---|
| S1 | ≤5 天 | 3.0 | -3.0 | 25% |
| S2 | ≤10 天 | 3.0 | -3.0 | 35% |
| S3 | ≤15 天 | 4.0 | -4.0 | 20% |
| S4 | ≤20 天 | 9.0 | -4.0 | 20% |
| 硬止损 | 任意 | — | -6.0σ | 全清 |

动态调整：PT 触发 → SL 上移（S1→breakeven, S2→+1σ, S3→+2σ）；SL 触发 → PT 下移（S2→1.5σ, S3→2.0σ）。

**σ 来源**：tracker 创建时用**信号 σ**（非自估）——与离线逐位一致。

#### 4.4.1 框架层改动（仅 2 处，均非提速）

| 文件 | 改动 | 理由 |

### 4.5 ⭐ 净值/收益/回撤计算审计与 5 个 Bug 修复（2026-08-31 深度排查）

**起因**：用户质疑"期末净值 990,204 但总收益 -1.59%"、"Eureka 期末 991,103 但收益 -3.79%"数字对不上。深度排查发现**对比脚本基准错误 + Eureka 侧 4 个实质 Bug**，全部修复后重测。

#### 4.5.1 收益基准错误（对比脚本，非框架）

| 项 | 错误口径 | 正确口径 |
|---|---|---|
| gpsef 总收益 | 以**08-01 建仓日收盘** 1,006,194 为基准 → -1.59% | 以**初始资金 1,000,000** 为基准 → **-0.98%**（gpsef report 官方口径：77.15% 即用初始资金） |
| Eureka 总收益 | 报告 -3.79%/-5.67%（来源混杂） | assets 首行 07-31=1,000,000 → **-0.89%**（旧数据） |

**机理**：gpsef `daily_values.csv` 无 07-31 初始行，首行即 08-01 建仓后收盘值（1,006,194，当日建仓上涨 +0.62%）；对比脚本 `nav=total/total[0]` 以首行为基准 → 系统性低估 0.61pp。Eureka assets 有 07-31 初始行 → 基准天然正确。**修复：对比脚本为 gpsef 前置 07-31=1,000,000 初始点，两框架统一以初始资金为基准。**

#### 4.5.2 Bug A（最根本）：分钟线后复权因子取错 → 建仓 5 分钟即错误触发 hard_sl

- **现象**：sz.300509 08-01 09:35 建仓，09:40 即触发"Stage4 止损 @23.949→raw 5.841"（-6σ hard_sl）；随后防御路径重建 tracker（真实价 entry）→ 与后复权 bar 错配 → 每 5 分钟循环荒谬"止盈"（raw=1.590，而真实价 6.4）
- **根因**：`datacenter._load_minute` 取因子用 `mdf["trade_date"].min()`（**数据文件起始日**，如 2019 年 → bf=2.996973），而 08-01 当日正确因子为 **4.100041**（2022-07-13 生效）→ 分钟 bar 后复权价系统性偏低 27% → `cur_s = (19.18/26.773-1)/0.0176 ≈ -16σ` → 触发 hard_sl
- **修复**：因子改按**回测当日**查询（缓存全表 `_factor_tables`，按 `dividOperateDate <= 当日` 取最新）→ 验证 adj=26.61（因子 4.100041 ✓）
- **影响**：修复前建仓次日 89 笔错误清仓（08-02），净值曲线完全失真

#### 4.5.3 Bug B：规则引擎无阶段门槛 → 持有 1 天 S1-S4 全触发

- **现象**：sz.300640 08-02 持有 1 天，S1-S4 四阶段 SL 全部触发（x1075+x1505+x860+x860=100% 清仓）
- **根因**：`staged_exit.check()` 只用 `stageN_done` 标记，**从不检查 `held_days`/`current_stage`**；gpsef `_check_staged_minute` 有 `current_stage(held_days)` 阶段门槛（S1:≤5d/S2:≤10d/S3:≤15d/S4:≤20d），移植时丢失
- **修复**：check() 计算 `active = tracker.current_stage(held_days)`，**只检查当前激活阶段**（hard_sl 全局兜底不变）+ 浮点容差 1e-9（`cur_s=-2.999999999999997` 恰好 -3σ 判负失败）→ 单元验证：持有 1d/-5σ→S1、1d/-7σ→hard_sl、6d→S2、11d→S3、21d→S4 全部正确
- **影响**：修复后 08-02 触发从 **89 笔 → 6 笔（全 S1）** ✓

#### 4.5.4 Bug C：防御路径 `_register_tracker` entry 口径错

- **现象**：tracker 被 pop 后防御重建 `entry_adj=6.460`（真实价）→ 与后复权 bar（26 量级）错配 → 荒谬触发（raw=1.590）
- **根因**：avg_cost（真实成交价）直接当 entry_adj
- **修复**：entry_adj 优先用 `cd.adj_close`（后复权），回退 `price×back_adjust_factor`；entry_raw 保持真实价

#### 4.5.5 Bug D：调仓语义未对齐 → **v8 完全对齐"先清后买"**

- **现象**：08-29 调仓 Eureka 只买 15 只（目标内已持仓 5 只跳过）vs gpsef 买 20 只 → Eureka 现金多 ~9 万、持仓结构分叉
- **根因**：`_execute_rebalance` 对 `cur_qty>0` 直接 `continue`（保留持仓）；而 gpsef 实证为**先清后买**（08-29 卖出 19 笔、其中 3 笔属于当日目标的旧持仓 = 全清旧仓，再全额买入 20 只）
- **修复（v8）**：改为 **① 卖出全部当前持仓（含目标内）→ ② 按 `target_value = 总资产×weight×scale` 全额买入全部目标**——与 gpsef `order_target_percent` 语义逐位对齐
- **效果**：08-29 total 差从 +57,603 → **+4,626**；首日 +23,994 → **-2,833**

#### 4.5.6 Bug E：缺失到期退出 → 持仓去化慢、仓位偏高

- **根因**：gpsef 有到期退出（`held_trade_days >= max_hold_days(20)` → 开盘价全清），Eureka 缺失 → 持仓去化慢 → 9 月下跌段仓位高 7pp → 回撤更深
- **修复**：`_check_exits` 加到期退出（held>=20 → 全清）+ `held_days` 从 `days//7*5` 近似改为**交易日历精确计算**（`_trading_days_between`）

#### 4.5.7 Bug F：分钟数据缺失 → 撮合静默未成交（v8 修复）

- **现象**：08-01 Eureka 只买入 19 只（20 目标缺 sz.301116），首日现金多 2.4 万（此前误归因为"取整损失"——**用户指出 gpsef 也 100 股取整后重新审计**：gpsef 取整损失仅 2.7%，Eureka 每笔达成率 90-100% 正常，真因是少买 1 只）
- **根因**：sz.301116 为 2022-01 次新股，**5min 数据仅从 2026-05-22 起**（2022 年无分钟数据）→ 撮合取分钟价失败 → WARNING "can not get price info" → 订单静默未成交
- **修复**：`get_price_data` 分钟分支在分钟数据为空时**回退日线 bar**（数据桥层容错，次新股/数据缺口自动降级）
- **效果**：08-01 买入 20/20 全成交，首日 Δ+23,994 → **-2,833**

## 7. 风险与注意事项

1. **实盘不训练**：Eureka 侧绝不 import gpsef 策略训练路径（信号文件是唯一输入）
2. **σ 一致性**：已通过信号 σ 解决——但若离线波动率参数（`vol_method/vol_ewma_lambda`）变更，需重新导出信号
3. **scale 时效性**：scale 是调仓日当天的回撤熔断/趋势过滤状态，信号需在调仓日盘前消费（错过则用最近信号）
4. **除权时间窗**：除权信号需在除权日盘前送达；若错过，需在下一日补发（`stock_ratio` 仍可应用）
5. **价格口径**：当前用前复权价（reference_date=20260804）与 gpsef 一致；实盘下单需换算真实价（gpsef 双轨价格体系）
6. **现金预算**：target_value 按总资产×weight×scale，实际买入可能因涨停/停牌部分落空，需再平衡机制（下一阶段）
