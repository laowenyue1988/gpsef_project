## 一、问题回顾

gpsef 执行端 `_check_staged_minute` / `_check_staged_daily_fallback` 的 `stage`/`held_days` 参数**形同虚设**：
S1-S4 由 `stageX_done` 标记无条件同时检查，任何持有天数可触发任意阶段。
config 中 `max_hold_days: 5/10/15/20` 的"阶段时长"注释含义在执行端不生效（仅 20 天到期清仓生效）。

**待决策**：① 改注释承认现状；② 真正启用 stage 持有期门槛（Eureka 端语义）。

## 四、两种方案的完整论证

### 方案 A：改注释（承认现状，维持 S1-S4 无条件同时检查）

**支持证据**：
1. 提前触发事件**净贡献为正**：S4-pt +19.97%、S3-pt +9.16%、S2-pt +7.96% 都是盈利的早期止盈；提前 sl 是早期止损保护（-3%~-7% 及时截断，避免拖到 -6σ）
2. 单日全清 `(1,2,3,4)` 71 例当日 -7.9%——加门槛只会把这些亏损推迟放大
3. 与 2026-09-01 用户裁决一致："gpsef 分阶段触发经充分回测验证，大跌击穿全清是合理设计"
4. 标签端 `simulate_staged_path` 已与执行端逐行核对（同一语义），**若执行端加门槛，标签端必须同步改**，否则训练/交易标签错配

**代价**：config 注释"持有天数 1~5 天"等与行为不符，需改注释；Eureka 端已有 current_stage 门槛（双框架语义分叉）。

### 方案 B：启用持有期门槛（Eureka 语义）

**数据代价（量化）**：
1. **S4-pt 提前止盈 101 笔（+19.97%，成交额 71.9 万）将被压制到第 16 个交易日后**——9σ 级别的暴涨通常在前 1-2 周内兑现，16 天后多数已回落 → **大概率损失这部分高收益**
2. S3-pt 提前 295 笔（+9.16%）同样被压制到 11 天后
3. S2-pt 提前 261 笔（+7.96%）压制到 6 天后
4. 提前 sl（S2 239 笔 / S3 284 笔 / S4 549 笔）被推迟 → 深跌通道中损失扩大，最终仍会触发 -6σ 硬兜底或到期清仓（held_td=20），**只是更晚、更亏**

**净效应估算**（粗略）：提前止盈的盈利贡献（101×0.20 + 295×0.09 + 261×0.08 ≈ 20+26.5+21 ≈ 68 单位收益）远超提前止损的损失（549×0.03 + 284×0.065 + 239×0.075 ≈ 16.5+18.5+18 ≈ 53 单位）——**提前触发整体是正贡献**，加门槛反而破坏。

**好处**：与 Eureka 一致；阶段语义"随时间推进"更符合直觉；避免单日全清（业界有争议）。

## 五、结论与建议

### 建议：**方案 A — 改注释，不启用持有期门槛**（维持现状代码）

**核心理由（全部基于本轮回测真实数据）**：

1. **提前触发是正贡献**：S2/S3/S4 的早期止盈（+8%~+20%）合计收益 > 早期止损（-3%~-7%）合计损失。阶段阈值本身就是"σ 事件驱动"——暴涨 9σ 就该兑现，与持有天数无关。
2. **加门槛的代价不可接受**：S4 有 82.8% 的触发在 1-15 个交易日，门槛会让 S4 名存实亡；单日全清（击穿保护）71 例会因推迟止损而扩大亏损。
3. **保持标签/交易一致**：当前两端同语义，改注释零风险；启用门槛需同步改 `simulate_staged_path` + 重训模型 + 重跑全窗口验证，成本高且大概率变差。
4. **符合既有裁决**：2026-09-01 已裁决 Eureka 对齐 gpsef（移除门槛），现在再给 gpsef 加门槛是走回头路。
