## 二、设计（★保守可逆：不改既有工具）

**核心立场**：D-118 引擎的 22/22 自检与「已公布数字逐位复现」结论**依赖其逐字输出** ⇒ 与 O-14（不编辑 `_o7_long_window_tables_v2.py`）同源处置：**不编辑引擎**，改用「包裹 + 逐字留痕 + 显式映射」三件套。

```
_wave5_arm_verdict.py --arm <名册臂|run_dir> [--control <run_dir>] [--outdir deliverables/wave5]
   │
   ├─ ① 名册解析：臂 → 窗口 → 控制臂（★硬编码 O-15 冻结名册，人工不参与配对）
   ├─ ② 硬门控：双臂 report.json 在档？（缺 ⇒ [BLOCK]/[ERR] + rc=2，不产出伪裁决）
   ├─ ③ 窗口一致性核验（config_full.json 的 start_date/end_date）⇒ 不一致 ⇒ [WARN]
   ├─ ④ O-7 三表 v2（_o7_long_window_tables_v2.py）⇒ 断言含 ①②③ 三个标记
   ├─ ⑤ D-77 分类（_d77_initial_sensitivity.py，S-12′ 口径）
   ├─ ⑥ D-118 引擎（_m9_e6_verdict.py）原始输出 ⇒ **逐字**入附录 §6
   └─ ⑦ 渲染 M11 主体：§0 标签映射 / §1 四档复现分类 / §2 三口径 / §3 三列敞口(O-13) / §4 D-77 / §5 必附清单
```

**★判据逻辑零复制**：包裹脚本以 `import _m9_e6_verdict as ENGINE` 方式**直接复用** `read_report()` 与 `evaluate()`。
⇒ 主体 §1 与附录 §6 的判定出自**同一实现** ⇒ 只存在**标签差异，不存在判据漂移**（这是本设计相对「复制判据 + 双份维护」的关键优势）。
