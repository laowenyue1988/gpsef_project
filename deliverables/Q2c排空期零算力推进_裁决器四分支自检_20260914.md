### 1.1 ★内存分析（本轮唯一风险项，结论：**不需要调参**）

**表面现象**：MemFree 在 **3.1~3.5GB** 区间，已 <4GB；且 `mem_gate_mb = 6000` 意味着
runner16 的**新臂启动门**（`fm < MEM_GATE_MB ⇒ break`）**当前处于「被自己的门挡住」状态**。

**机理核算（三步）**：

1. **臂内存正在长**：三臂实测 **4.4~5.3GB**（SL050 4.69 / SL060 5.25 / PT125 4.39），
   与记忆基线一致（长窗单臂 5.5→7.3GB 常驻）⇒ 全长成时 ≈ 17~22GB。
2. **总内存 31.5GB** ⇒ 3 臂全长成后 MemFree 仍应有 **9~14GB** 余量；
   当前低水位是**三臂同时进重训窗口**的瞬时叠加（重训期 CPU 密集型 pandas 中间体）。
3. **对「接棒」的影响**：`SL050` 于 19:09~19:11 排空后，runner16 空出 1 车道。
   此时**恰好有一臂退出** ⇒ 其 4.7GB 释放 ⇒ MemFree 回升至 ≈8GB > gate 6GB
   ⇒ **`SL070` 能正常接棒**（退出与启动同轮，门槛不会被卡）。

**⇒ 判定：零调参**。若出现「`SL050` 已排空但 `SL070` 超过 2 轮巡检仍未启动」，
才说明 gate 需下调（届时按 6000 → 5000 单步调整并留痕）。

**★三条结构性推论**（自检的机器结论）：

1. **D 是「并列附加」**：只要 `SL070` 的长窗 ★Sharpe < 基线，D **恒**与 A/B 并列出现
   （与「是否另有臂达标」无关）。这正是 D-181 的语义 —— κ=0.7 低效 ⇒ 窗口类型依赖失效，
   **须并行启动结构性调查**，而非替代 A/B 判定。
2. **C 的两条件是「或」**：任一条成立即触发（`初版工具把两条都要求」是错的 —— 已在自检中纠正）。
3. **★「B ∧ 无 C ∧ 无 D」是可构造的**（穷举 3750 组取证）——
   唯一构造 = `SL070 ≥ 基线`（D 不触发）＋ `SL060PT125` 为 long_best（无 C，因最优==短窗第一 且 κ0.6>κ0.5）
   ＋ **`SL060PT125` 的 Calmar < 基线**（故不算达标 ⇒ B）。
   ⇒ **该子型 = 「长窗最优臂 Sharpe 够、Calmar 不够」**。裁决轮若判出纯「B」，
   **必须**核对该臂的 Calmar，并在结论中写明这一子型（否则会误读为「该轴全面失效」）。
