## 3. ★★R-148（新登记【中】）· 启动器 CRITICAL 日志实参错位 ⇒ 审计读数虚假

### 3.1 第一手事实

启动器 47 条 CRITICAL 行的**尾部读数恒等于 `avail`**，非 `commit_free`：

```
[2026-09-18 07:05:42] 🚨 CRITICAL 可用内存 3552MB < 4000MB ⇒ **暂停启动**（不杀在跑臂）；活跃臂=3 提交可用=3552MB
```

而本自动化同期（07:27~07:31，5 次采样）实测：

| 口径 | 读数 |
|---|---|
| `avail_phys`（GlobalMemoryStatusEx.ullAvailPhys） | 3614 ~ 4272 MB |
| **`commit_free`（A 路径 `ullAvailPageFile`）** | **38256 ~ 38849 MB（37.4~37.9 GB）** |
| `commit_free`（B 路径 `CommitLimit − CommitTotal`） | **38849 MB** |
| **两路径 \|diff\|** | **0 MB** ⇒ 口径互证 ✅ |

⇒ 启动器记的 "提交可用=3552MB" 与真实值 **38.8GB 相差 ~10.9×**。

### 3.2 行号级取证（根因）

**`_q5l_launch.py:220~222`（CRITICAL 分支）**：
```python
if mm['avail'] < DANGER_MB:
    log('🚨 CRITICAL 可用内存 %dMB < %dMB ⇒ **暂停启动**（不杀在跑臂）；活跃臂=%d 提交可用=%dMB'
        % (mm['avail'], DANGER_MB, len(act), mm['avail']))   # ← 末个实参是 avail，不是 commit_free
```
格式串请求 4 个整数，实参元组第 4 项写作 `mm['avail']` ⇒ **`mm['commit_free']` 从未被打印**，"提交可用"一栏**恒等于 avail**。

**对照证据（同文件另一处，实参正确）** `_q5l_launch.py:256~257`（启动分支）：
```python
log('▶ 启动 %s (pid=%d, %s) ｜ 活跃臂 %d→%d/上限%d ｜ 可用 %dMB（提交可用 %dMB）%s'
    % (n, pr.pid, det, len(act), len(act) + 1, GLOBAL_MAX_ARMS, mm['avail'],
       mm['commit_free'], ...))   # ← 此处正确传入 commit_free
```
⇒ **同一变量在两处一处对、一处错** ⇒ **是格式串/实参错位，不是采集字段取错**。

**`_q5l_launch.py:78~79`（采集本体）**：
```python
return {'total': m.ullTotalPhys // MB, 'avail': m.ullAvailPhys // MB,
        'commit_free': m.ullAvailPageFile // MB, 'load': m.dwMemoryLoad}
```
`ullAvailPageFile` = 提交余量，**取值正确** ✅ ⇒ 启器**内部闸②判据用的是正确值**。

### 3.3 后果（关键：保护有效性不受影响）

- **闸逻辑健全**：闸①（`len(act) ≥ GLOBAL_MAX_ARMS=3`）、闸③（`avail < DANGER_MB=4000`）、闸②（`avail<GATE_MB=6000` **或** `commit_free<20000`）三者**独立**，且**均用正确值**；启动器**从不杀在跑臂**。
