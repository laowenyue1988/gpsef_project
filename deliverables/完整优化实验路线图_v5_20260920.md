| **③ 每臂对应假设** | **R0** = 现行基线（**零算力**，= `S17b_SL060PT150`）｜**R1~R5 = 5 个随机种子**（唯一变量 = `preds` 换成**逐日截面均匀随机分位**，其余逐键相同）|

**关键设计**
- **唯一变量 = 预测值**；`staged_exit` / 池 / 仓位约束 / 费用 **逐键不变**（沿用 Q5N 的闸⑥逐键 diff + 闸④零影响闭合）。
- **随机分位取 top-20 ≡ 池内随机挑 20 只等权** ⇒ **同时等价覆盖**朋友的两条建议（"随机打分 20 次" + "不过模型的等权买入"），**无需 V10/Wyckoff**。
- **N 的两阶段取法（控算力）**：先跑 **5 个种子全窗**（2 波 × 3/2 臂，**≈22h**）。**判读规则**：
  - 基线 **> 5/5 种子最大值** ⇒ **定性已足**（随机上界远低于基线）⇒ 继续优化主线；
  - 基线**落在 min~max 区间内** ⇒ **191 无贡献 ⇒ 触发重大路线调整**；
  - 落在边界 ⇒ 再补 15 个种子（不必一次跑 20）。
- **预注册判据 R-1~R-5**
  - **R-1 有效性闸**：随机臂无崩溃（ERROR=0 / 训练失败=0 / 调仓 >0 / 零持仓轮=0）；
  - **R-2 主判据**：现行基线的 **★Sharpe ＋ ★Calmar ＋ 单位敞口** 三点是否**同时**超出随机分布；
  - **R-3**：分段归因（WD / WX / 2026）+ **敞口序列**；**必同引 D-150**；
  - **R-4**：D-174 仅作参照；
  - **R-5 可反驳**：**基线与随机分布不可区分 ⇒ 判定「191 在当前框架内未产生可检测贡献」**，路线转入「Q5V 上层接入」或「新因子挖掘」主线。
- **★限制（必须同引）**：① `max_positions=20` 使"池内全等权（300 只）"**不可实现** ⇒ 本批检验的是「**随机 20 只 vs 模型选 20 只**」，不是「全池等权」；② 随机分布只刻画"零信息"，**不排除"191 有用但被出场机制抵消"**；③ 5 个种子是**分布上界估计**，非完整 20 次分布（诚实标注）。
- **前置条件（硬）**：需**源码改动**（新增 `preds` 随机化路径）⇒ **必须等 Q5D 落臂后**（R-130 `guard-edit` 生效中）；且须过 **R-126 真回测烟测四项** ＋ **R-127 缺陷区间覆盖**（烟测窗含 2024-04~2024-08）＋ **`_exp_version.py preflight`**。
- **算力预算**：5 臂 × ≈11h ÷ 并发 3 ⇒ **≈22h（2 波）**；**全局并发不超 3**。

**为什么排在 Q5D 之后**：① 源码改动被 `guard-edit` 阻断；② Q5D 若胜出会改变敞口路径 ⇒ 随机臂须以 **Q5D 胜出配置**为共同 BASE，否则要重跑；③ 全局并发 ≤3 硬约束。

### 4.3 Q5E · 组合终验 + 最终《落地建议书》★交付终点

1. **组合终验**：在**最终确认的目标 + 胜出参数包**上跑长窗 1315 日（ADOPT 臂）。

## 5. 运维与纪律（防事故）

### 5.1 进程与内存

| 纪律 | 内容 |
|---|---|
| **单一执行者** | 同一批次只允许**一个执行者**（监督器/启动器）；自动化与其它角色**只读监控 + 分析 + 通知** |
| **全局并发臂 ≤ 3** | 判据 = `results/*/backtest.log` mtime 龄 <300s 且无 `report.json` 的目录数（**排除归档目录**）|
| **内存判据** | **只看「提交余量」**：>10GB 安全；<15GB ⇒ 降 2 臂；<8GB ⇒ 降 1 臂并告警（`ullAvailPhys` **偏乐观，不得单独作依据**）|
| **长驻唯一形态** | **受管后台任务 + `2>&1 \| tee`**，父进程全程存活；**不再尝试任何"脱离"手段** |
| **判活/判完成** | **一律产物信号**（`report.json` / `backtest.log` mtime / 批次日志）+ **起臂后初始化宽限 1500s**；**禁用 PID，也禁用返回码**（`os.execvp` 自我重执行）|
| **判死** | 必须 `tasklist` + 产物信号**多证据交叉** |

### 5.2 实验版本管理三闸门（R-130，`_exp_version.py`）

| 闸门 | 时机 | 拒绝条件 |
|---|---|---|
| `preflight` | **起臂前** | 版本漂移未声明；**已有臂在跑且源码 mtime 晚于该臂起臂时刻** |
| `guard-edit` | **改源码前** | 存在在跑臂（已内置 `_apply_q5n_patch.py`）|
| `audit` | **落臂后 / 读数前** | `provenance` 中途改码 / R-127 四类错误 / 零持仓轮 / 无调仓 ⇒ 判 `VALID/INVALID/INCOMPLETE/RUNNING`，**INVALID 禁止进判据** |

- **登记表**：`_exp_registry.json`（机器）+ `deliverables/EXPERIMENTS.md`（人读）
- **冻结基线**：`_exp_frozen.json`

### 5.3 每次实验后的标准动作（**流程硬约束**）

```
落臂 → ① audit（版本/健康）→ ② 深度分析（R-105 + 分段归因 + 交易层）
     → ③ 三件套裁决（分析 + 路线全盘对账 + 裁决，写明否定路径 or 机制）
     → ④ 同步 MEMORY + deliverables → ⑤ 才进入下一阶段
```

**未出三件套不得进入下一阶段。**

### 5.4 ★新增纪律（R-133）：外部质询处置

**凡外部质询（同行 / 评审 / 朋友），必须先做零算力事实核对（代码 + 配置 + 已有产物）再答复**；答复中凡方向性判断须附**代码位置或实测数字**；**事实有误处须明确纠正（含对我方有利的纠正）**，不得含混。
