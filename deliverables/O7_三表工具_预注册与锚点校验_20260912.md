## 一、动机

O-7 要求 M9/M10 长窗裁决必须附「时段分解 + 优势集中度 + 单日贡献」三表。E6/DD 五臂将于 **09-13 05:00~06:30** 陆续完成 —— 若届时才手工推导，既耗时又易错（M8 手工推导过程中曾出现「切片区间取 `[start,<end)` 导致漏边界日」与「空仓段口径误取 触发日→恢复日」两处错误，均已勘误）。

因此本轮利用**零回测机时**，先把 O-7 做成**可复现、可自检**的脚本。用户令要求「若修改了代码，务必充分测试代码改动，确保改动符合预期」⇒ 本轮以 **M8 已公布的 10 个数字**作锚点做回归断言。

## 二、工具设计（口径与边界定义）

| 项 | 定义 | 理由 |
|---|---|---|
| 收益序列 | `results/<run>/daily_values.csv` 的 `total_value` | 唯一可复现的逐日净值 |
| 全期基准 | **首个记录日 NAV → 末记录日 NAV** | 与 M8 口径一致（`report.json` 的 `total_return` 含首日收益，仅作参考列） |
| 空仓段 | `daily_return` **连续恒 0**（容差 1e-9，连续 ≥3 日）的平台 | 与「清空目标 ⇒ 无持仓 ⇒ 零收益」一一对应，比日志更可靠 |
| 空仓段首日 | 平台**前一日**（清仓调仓日，该日仍有收益） | M8 已验证：重建日收益**不得**并入空仓段 |
| 熔断触发日 | 含空仓段首日的「连续越阈块」的**首个**越阈日（NAV 相对历史峰值 ≤ −dd_flat） | 跨臂口径统一；`dd_flat` 自动读该臂 `config_full.json` |
| 分段 | 边界 = {0, 触发日, 空仓段首日, 空仓段末日, 重建日, n−1}，相邻段**共享边界日 NAV** | **Π(1+r_i) 严格 = 全期**（脚本内硬自检，不通过拒绝出表） |

**双触发口径披露**：日志的日期标记对**非调仓日事件会滞后**（`FLAT→NORMAL` 行实测被标为 2024-08-02，真实恢复日 2024-08-27），故**切分一律不依赖日志**；脚本对每个空仓段并列输出 `block`（默认，跨臂统一）与 `first`（回溯窗内最早越阈日）两个触发日，差异显式披露。

**用法**

```bash
# 自检（锚点回归套件）
python _o7_long_window_tables.py --self-test
# 出表（M9/M10 裁决时使用）
python _o7_long_window_tables.py --arm <run_dir> --control <同窗控制臂run_dir> --out <md>
```
