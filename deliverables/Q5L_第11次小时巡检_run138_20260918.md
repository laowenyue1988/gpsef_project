```
2026-09-18 13:55:08,267:strategies.small_alpha191_test3.strategy:INFO:[B1] 中性化 fit 剔除生产 val 段: 全 240 天 → fit 用 220 天 (cutoff=2026-01-13, 剔除 20 天)
```

即 `[B1]` 位于**行中部**（前置 `时间戳:模块:INFO:`）⇒ 首版 **全部 0 命中**、`ratio=nan`。
**修正为全行子串匹配 `"[B1] 中性化 fit 剔除" in l` ＋ 唯一 `cutoff=` 自证**后复跑得 **61/61/62、ratio 全 1.0000 PASS**。

**交叉核验**：外部 `grep -c B1` 独立复核 = **61 / 61 / 62**，与 Python 读数**完全一致** ✅
⇒ ★**R-147 口径的正确表述 =「进度 = 含 `[B1] 中性化 fit 剔除` 的整行计数（配唯一 `cutoff=` 数自证）」**，**不是** `startswith("[B1]")`、**也不是**数值解析 N/TGT/CV。下轮起统一沿用。

### ★R-150 候选【低】：进程内内存读数冻结伪影

**第一手事实**：`_p138_mem.py` 与 `_p138_rev.py` 在**同一进程内连续 5 次采样**，5 次读数**完全相同**
（`avail_phys` 分别恒为 1026MB / 1400MB，`commit_free` 分别恒为 22672MB / 22984MB，span **=0MB**）⇒ 初判"内存冻结异常"。

**取证**：改为**每次独立进程调用**（`_p138_one.py` × 6 次），读数**正常波动**：
`avail_phys` 1390 / 1353 / 1378 / 1966 / 2323 / 2766MB，`commit_free` 22977 / 22943 / 22969 / 23512 / 23882 / 24363MB，
`CommitTotal` 14436290 / 14445109 / 14438499 / 14298883 / 14204731 / 14081473 **逐次不同** ⇒ **采集函数本体无误**。

**⇒ 结论**：冻结是**同一进程内多次调用 `GlobalMemoryStatusEx`/`GetPerformanceInfo` 在沙箱内的读数缓存伪影**，
**不是**真实内存状态，**不是**采集逻辑错误。
**影响**：仅**采样粒度**；**内存安全结论不受影响**（独立进程六次采样互证一致）。
**处置**：列**候选【低】**（影响仅监测侧、正解已确定），**不登记为正式 R**。
★**新纪律**：内存采样**必须跨进程独立调用**（每采样一次起一个进程，或加 ≥1s 间隔并校验 `CommitTotal` 变化），
**禁止以进程内多次采样的 span=0 判"内存稳定"**。

**★R-108 判别力自证（第 14 例）**：
- 反例 A（`b1=61, uniq=61`）⇒ **PASS**（应 PASS）✓
- 反例 B（`b1=61, uniq=60`）⇒ **FAIL**（应 FAIL）✓
⇒ 判据能区分「计数一致/不一致」，**判别力成立** ✅

**★附带纠正（避免误读）**：`GetPerformanceInfo` 的 `CommitTotal`/`CommitLimit`/`PhysicalAvailable`
单位为 **PAGE 数而非字节**，须乘 `PageSize`（实测 4096）。首版未换算 ⇒ `commit_free_B` 恒为 6MB、`PhysicalAvailable` 恒为 0MB。
**换算后双路径互证**：`ullAvailPageFile` 与 `(CommitLimit−CommitTotal)×PageSize` **`|diff| = 0MB`**（6/6 次采样中 5 次为 0、1 次为 2MB）✅
