# Purged K-Fold 特征筛选方式 · 标准性论证

> 针对 `Alpha191_因子管线审查报告_20260805.md` 第七节的疑问：
> "每折用训练部分独立选特征"是否符合 Purged K-Fold 特征筛选的标准做法？
> 为什么要在折内选特征？不是应该有 4 折训练、1 折验证吗？
>
> 本文基于本地最新代码（`strategies/hs300_alpha191/ensemble.py` `_purged_kfold_cv`）与业界标准（López de Prado《Advances in Financial Machine Learning》§7.4；Cawley & Talbot 2010）论证。

---

## 一、结论先行

**项目流程符合 Purged K-Fold + 嵌套特征选择的标准做法，且"4 折训练、1 折验证"正是该项目在做的——两者是不同层面的东西，不存在矛盾。**

| 层面 | 用户说的"4 折训练 1 折验证" | 项目实现 | 是否符合 |
|---|---|---|---|
| **外层：模型评估**（K-Fold CV） | 每折 K−1 部分训练 + 1 部分验证 | ✅ 每折 1 个时间块验证、其余块训练（purge+embargo=21） | 完全符合 |
| **内层：特征选择**（嵌套 CV） | （被混淆为"在折内训练"） | ✅ 每折在**训练部分内部**重新选特征，验证块零接触 | 符合（深度为简化版） |

**关键澄清**：文档/代码中的"折内特征选择"不是"折内训练模型"，而是"特征选择嵌套在训练部分内部执行"。IC/PSI 是统计计算（不需要训练模型），项目在每折的训练数据内部按时间切前 50%（IC 子集）/后 50%（PSI 子集）完成特征筛选。**这正是嵌套 CV（Nested Cross-Validation）的标准精神。**

---

## 二、为什么"折内选特征"是必要的（选择偏差）

### 2.1 如果"先用整段数据选特征，再 4-1 折训练"会怎样？

这是**最经典的机器学习错误**——非嵌套 CV 的选择偏差（selection bias）：

1. 用**全部数据**（含所有验证块）做特征选择；
2. 特征选择过程"看到"了每个验证块的答案（标签）；
3. 选出的特征集天然偏向"在全部数据上都预测得好"的因子；
4. 后续 K 折验证时，验证块对这些"偷看过自己答案"的特征表现虚高；
5. **结论：验证 AUC 乐观偏倚，生产模型实际表现低于评估值。**

**经典文献**：Cawley & Talbot (2010) *On Over-fitting in Model Selection and Subsequent Selection Bias in Performance Evaluation*——论文用大量实验证明：**嵌套 CV（特征选择在每折训练部分内部做）得到的泛化误差估计显著更真实**；非嵌套 CV 会系统性高估模型性能，且特征越多、候选特征越多，偏倚越严重（本项目候选 302 个特征 → 偏倚风险极大）。

### 2.2 金融时序场景的特殊性（更严重）

- 本项目标签 = 未来 20 天收益；
- 若特征选择看了验证块数据 → 等价于用"未来价格"选因子；
- 这不仅是统计偏倚，而是**直接的前视偏差（look-ahead bias）**——比普通机器学习更不可接受。

### 2.3 形式化理解

设全量数据 $D$，特征选择器 $\mathcal{S}$，评估器 $\mathcal{E}$（K 折 CV）。

- **非嵌套**：特征集 $F^* = \mathcal{S}(D)$ 用了全部数据 → $\mathcal{E}(D, F^*)$ 的验证块信息已渗入 $F^*$ → 估计 $\hat{R}$ 偏乐观：$\mathbb{E}[\hat{R}] > R_{\text{true}}$（Cawley-Talbot 结果）；
- **嵌套（本项目）**：每折 $k$，特征集 $F_k = \mathcal{S}(D \setminus D^{\text{val}}_k)$（只用训练部分）→ 验证块 $D^{\text{val}}_k$ 与 $F_k$ 独立 → $\hat{R}$ 无偏（在 purge 正确的条件下）。

## 三、项目实现逐项对照（Prado AFML §7.4）

项目代码（`ensemble.py` `_purged_kfold_cv`，参数来自 config：`cv_folds=5, cv_embargo_days=21, cv_feature_consensus=1, cv_ic_psi_split_ratio=0.5`）：

```python
for i in range(K):                                   # ① K=5 时间块
    val_dates  = 块 i                                 # ② 每块轮流当验证
    train_dates = 非验证块 − [验证块前后各 embargo=21 天]  # ③ purge
    fold_defs.append((train_dates, val_dates))       #   保存折定义(供CV集成)

    train_set = df[isin(train_dates)]                # ④ 训练部分
    # ── 折内特征选择（嵌套, 只用训练部分）──
    ic_dates  = train_unique[:50%]                   # ⑤ 训练部分前半 → 算 RankIC
    psi_dates = train_unique[50%:]                   #   训练部分后半 → 做 PSI 对比
    fold_feats = select_stable_features(ic_set, psi_set, ...)   # ⑥ 折内特征集

    # ── 折内模型训练 + 验证评估 ──
    model.fit(train_set[fold_feats], y_tr)           # ⑦ 折内训练（这就是"4-1"）
    auc_val = metric(y_va, model.predict(val_set[fold_feats]))  # ⑧ 验证块评估
    # ⑨ OOS MDA: 在验证块上逐特征置换 → 特征重要性
```

| 要素 | Prado AFML §7.4 标准 | 项目实现 | 状态 |
|---|---|---|---|
| 折划分 | 时间顺序切 K 块、每块轮流验证 | K=5 时间块轮流 | ✅ |
| Purge | 剔除验证块前后标签重叠样本 | embargo=21 ≥ max_hold=20 | ✅ |
| 训练集 | 非验证块（含未来块，非 expanding） | 非验证块（前后 purge） | ✅ |
| 特征选择 | 嵌套在折内（训练部分内） | 折内 IC/PSI（train 内部切子集） | ✅（简化嵌套） |
| 验证评估 | 验证块完全隔离 | 验证块 AUC（特征零接触） | ✅ |
| 跨折特征 | 只在稳定多折出现的特征保留 | 共识：出现 ≥1 折 → 生产特征集 | ✅（阈值宽松） |
| 最终模型 | 共识特征 + 全部数据重训 | 共识特征全量重训 + CV 折集成 | ✅ |
| OOS 特征重要性 | 验证块置换重要性（MDA） | 每折验证块 MDA（Prado 标准） | ✅ |

**结论：项目实现了标准的"外层 Purged K-Fold 评估 + 内层折内特征选择"，即嵌套 CV 的标准形态。**

## 四、诚实指出的 3 个差异点（不影响"符合标准"的定性，但值得关注）

### 差异 1：嵌套深度是"一层半"，不是完整两层

- **严格嵌套 CV**：训练部分内部再做一层 K 折 CV 来选特征/调参（两层）；
- **项目实现**：训练部分内部按时间直接切前 50%（IC）/后 50%（PSI）子集做统计筛选（一层半）。
- **为何可接受**：① 完整两层 CV × 外层 5 折 × 内层 5 折 = 25 次模型训练，成本高昂；② IC/PSI 是无需训练的统计筛选，直接按时间分割即可获得"训练部分内无未来"的干净估计；③ 验证块自始至终零接触 → **选择偏差已被消除**，只是没有额外的内层模型评估。
- **业界实务**：许多量化系统正是"折内统计筛选 + 验证评估"这一形态（Prado 的 MDA 流程同样在折内做重要性评估）。若追求更严格，可在 train 内部再套一层 Purged K-Fold，但收益/成本比低。

### 差异 2：`cv_feature_consensus=1` 非常宽松

- 特征出现在 **≥1/5 折** 即进入生产特征池——约等于取并集；
- **初衷**：hs300 等大票池存在大量折特征选择失败（实测约 80% 折因"有效特征<10"跳过），若提高共识阈值会进一步饿死特征池；
- **代价**：单折选出的"偶然特征"也能入选，跨折稳健性过滤减弱（Prado 建议 ≥ 多数折）。
- **建议**：折成功率高的策略（如 small 池）可提高 consensus 到 2~3；折成功率低的策略维持 1 并接受其代价。

### 差异 3：折内特征选择与生产特征集存在"窗口错配"

- 折内选特征用的是**折的训练部分**（约 151 天），而生产模型最终用**全部训练数据**（约 240 天）重训；
- 特征在 151 天子集上被选中、在 240 天全量上训练——特征集与训练范围不完全一致，理论上会轻微削弱特征选择与最终模型的匹配度；
- 这是业界常见的工程取舍（全量重训让模型用足数据）；严格做法是"折内选 → 折内训 → 折内评"三合一（项目正是如此），生产阶段再全量重训（业界标准）。

## 五、最终回答（对用户三个问题的直接回应）

**Q1：这个流程符合使用 Purged K-Fold 进行特征筛选的标准做法吗？**
✅ **符合**。项目 = Prado AFML §7.4 标准 Purged K-Fold（时间块 + embargo=21 + 验证块隔离）+ 嵌套 CV 特征选择（折内训练部分内选特征）。与 Cawley & Talbot 2010 推荐的嵌套结构一致。

**Q2：为什么要在折内（选）特征？**
因为**特征选择绝不能接触验证数据**。在折内（训练部分内部）重新选特征，是为了让每个验证块对特征选择完全"不可见"，从而：
1. 消除选择偏差（非嵌套 CV 的验证分数虚高，Cawley-Talbot 2010）；
2. 金融场景下避免用"未来价格"选因子的前视偏差；
3. 每折独立选 + 跨折共识，顺便度量特征稳定性（只在少数折有效的特征是"偶然特征"）。

**Q3：不是应该有 4 折充当训练集、1 折充当验证集吗？**
**这正是项目在做的**（外层 K-Fold：每折 1 块验证、其余训练）。"折内特征选择"是**嵌套在训练部分内部的另一层**，不是替换外层 K-Fold。两层的分工是：
- 外层（4-1 折）：评估"用这套特征训练的模型"在未见验证块上表现如何；
- 内层（折内）：在训练部分内部决定"这折用哪些特征"——验证块不参与。

如果"先用整段数据选好特征，再 4-1 折训练"，那特征选择就偷看了验证数据 → 验证分数虚高 → 生产模型真实表现打折扣。**所以折内选特征不是多余，而是嵌套 CV 的必要一环。**
