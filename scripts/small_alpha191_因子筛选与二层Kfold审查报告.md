## 二、因子验证三件套审查（是否多余？）—— 第一版结论不变

### 2.1 三件套设计定位与现状（代码实证）

`factor_validator.py` 的 `run_rebalance()` 在 PKF 之前执行（strategy.py L2814，`cycle % run_interval == 0`），投票剔除 `features_to_remove` 后再进入 ensemble。

**最近回测实际投票表现**（SmallAlpha191_20260816110527）：

| 组件 | 每周期投票 | 实际作用 | 状态 |
|---|---|---|---|
| SHAP 时序探针 | **SHAP=0/302（恒 0 票）** | 从未剔除任何因子 | 结构性失效（见 2.2） |
| 对抗性 ADV | ADV=5（恒定 5 票） | 疑似只标记低信息特征 | 与 IC/低方差重叠（见 2.3） |
| 条件 IC（CIC） | CIC=65~81（唯一实质投票者） | 每周期剔除 64~81 个因子 | 机制冲突 + 实证误杀（见 2.4）；**config 已置 enabled:false** |

### 2.2 SHAP 时序探针：结构性失效（0 票的根因）

**设计**：每期训练轻量 XGB（depth=6, 100 轮），TreeSHAP 算 train/val 的 mean|SHAP|，逐特征 ratio = val_SHAP/train_SHAP < 0.35 判"衰减"。

**为什么永远 0 票（数学 + 时间尺度论证）**：
1. **时间尺度错配（根因）**：因子衰减是慢变量（6~12 个月逐渐失效）；探针对比的是"整个训练窗口（约 1 年）vs 最近 20 天"——**两者都在同一有效期内**，结构相近，比值恒 ≈ 1；
2. 阈值 0.35 意味着 20 天内重要性崩 65%，对慢衰减因子几乎不可能；
3. 2026-08-01 注入测试已证实：人为注入衰减也无法触发 → **设计性失效，非代码 bug**。

**结论**：SHAP 探针是纯计算开销（每周期 ~2 分钟），**0 贡献**。它想解决"因子衰减预警"这个真问题，但窗口设计使其无法工作。

### 2.3 ADV 对抗验证：与 IC/PSI 粗筛功能重叠

**设计**：训练一个"区分 train/val 分布"的分类器，AUC>0.65 判分布漂移。

**问题**：
1. 恒定 5 票说明它几乎不工作——train/val 是同源时序切分（前 80% vs 后 20%），因子分布本身接近，分类器学不出区分度；
2. 即便工作，它检测的"分布漂移"与 ensemble 内 `select_stable_features` 的 **PSI 检查（分布稳定性，阈值 0.15）功能完全重叠**——PSI 在 PKF 每折内部做，且是统计量（无分类器方差），更优；
3. 从信息论看：ADV 的"可区分性 AUC"与 PSI/KS 检验是同一类"分布距离"度量，双份实现冗余。

### 2.4 CIC 条件 IC：机制冲突 + 实证误杀（本审查最严重问题）

**设计**：按市场状态分桶算 RankIC，若 IC 符号翻转（某些桶 >+0.03 且另些 <−0.03）或范围过大（>0.10）则剔除。

**实证误杀（test_cic_empirical.py，真实数据）**：

```
CIC剔除组(79个): MDA均值 0.00185, 86% 因子 MDA>0   ← 树模型中很有效!
保留组(131个):   MDA均值 0.00025, 61% MDA>0
被CIC剔除但MDA>保留组中位数: 64/79 (误杀候选)
被CIC剔除且MDA<0(该杀): 0 个
典型: alpha_068 (MDA=0.050) 被CIC剔除但却是XGB顶级特征
```

**CIC 剔除的因子在树模型中的平均重要性是保留组的 7 倍，0 个该杀**——方向性地反向筛选。

**三视角论证**：
- **数学**：CIC 的"符号翻转才有效"假设对**线性模型**成立（线性系数符号即方向）；但决策树用**分段常数逼近任意单调/非单调关系**，`if 熊市 then 用因子A` 正是树的分支结构。符号翻转的条件因子是**树模型的优势区**，CIC 判定"方向不稳定即无效"在树模型下**逻辑不成立**（非单调关系：CIC 的秩相关盲区，但树可捕捉）；
- **经济学**：金融存在真实的条件性因子——波动率因子震荡市防御（负溢价）/趋势市追涨（正溢价）；流动性因子危机期挤兑含义相反。符号翻转不是噪声而是**状态依赖机制**，应"条件化使用"而非"删除"；
- **ML 实践**：特征选择度量必须与模型类匹配（Prado MLAM §6-8）。用线性 IC 筛选树模型特征是**方法论错配**。已有 Purged K-Fold MDA 投票是模型内精筛器，CIC 在它之前硬删 = 把 MDA 想用的特征提前销毁。

**当前状态**：config `conditional_ic.enabled: false` 已禁用 CIC——**这是正确的**，但三件套框架本身仍在运行（SHAP 空转 + ADV 冗余）。

### 2.5 三件套"是否多余"的最终结论

**在当前架构下：功能上多余，机制上部分有害。**

| 论证维度 | 结论 |
|---|---|
| **功能重叠** | 三件套的"粗筛"职能已被 PKF 内部覆盖：低方差（VarianceThreshold）+ RankIC(0.001) + PSI(0.15) 三层已在每折内做，且**验证块零接触**、无分类器方差 |
| **机制冲突** | CIC 的符号翻转判定与树模型能力方向相反（实证 7 倍反向重要性） |
| **成本收益** | SHAP 探针 0 票纯开销；ADV 恒 5 票冗余；CIC 已禁用 |
| **唯一价值** | ①因子衰减预警（SHAP，但当前实现失效）；②审计/诊断输出（cfi_importance 等） |

**业界定位澄清**：特征筛选的正确分层是——**粗筛（快、便宜、只除纯噪声：低方差/缺失率/极宽松IC）+ 精筛（模型内 Purged CV 的 MDA 投票，与模型一致）**。三件套试图插入"中间层"，但用的度量（SHAP 时序/ADV/CIC）与树模型不一致。**在有 PKF MDA 投票的前提下，三件套作为"投票剔除成员"是多余的；作为"诊断工具"有保留价值。**

## 三、CV 结构审查（第二版重写：从"二层 K-Fold"改为"单层 Purged K-Fold"）

### 3.0 命名澄清：当前不是"二层 K-Fold"，实为"单层 Purged K-Fold 双用途"

**用户质疑成立。逐行核对代码后的结论：**

```
ensemble.py L1797  _purged_kfold_cv():
  for i in range(K):                       ← 唯一的一层交叉验证
    折内: select_stable_features (IC/PSI)  ← 折内粗筛（嵌套原则的正确部分）
    折内: xgb.train + 验证块AUC            ← 用途B：性能评估
    折内: compute_mda_oos(验证块)          ← 用途A：特征重要性
  折后: feature_counts 跨折统计 → consensus_features   ← 折后处理
  折后: aggregate_fold_votes (投票+评分+TopK)          ← 折后处理
  meta_auc = mean(fold_aucs)               ← 用途B：门控输入
```

- **真正的嵌套 K-Fold（nested CV，Cawley-Talbot 2010）** = 外层 K 折评估泛化 + **内层循环在每折训练部分内独立完成"特征选择 + 超参选择"**，外层验证折只被评估一次；
- 当前实现：**同一批折划分双重使用**（选特征 + 评性能），折内只有"IC/PSI 粗筛 + 单组固定超参训练"，**没有内层循环，更没有内层超参选择**；
- 因此：注释里的"嵌套 Purged K-Fold"（L1800）名不副实——它只做到了"折内特征选择只用训练部分"，这是嵌套原则的一半，另一半（内层超参选择、外层评估隔离）缺失。

### 3.1 现有 Purged K-Fold 的合理部分（保留）

- K=5 时间块轮流验证 + **embargo=21 ≥ max_hold=20**（比 Prado 建议的 0.5~1×horizon 更严）✓
- 标签窗口重叠已消除（数学验证：训练样本 T∈[0,26]∪[116,239] 的标签窗口与验证块 [48,95] 无交集）✓
- 时间有序、块不相交 ✓
- 折内 IC/PSI 特征选择只吃训练部分（前 50% IC / 后 50% PSI），**验证块零接触** ✓

### 3.2 核心问题①：缺少超参数选择机制（用户指出的最大问题）

**代码实证**：
1. **回测主流程无任何超参搜索**：strategy.py 全部 XGB 参数来自 config.yaml 固定值（`xgb_max_depth=4, eta=0.03, ...`），`xgb.train` 直接使用（ensemble.py L2252-2269、L2480-2485）；
2. **optuna 接口未接入**：`__init__.py` 的 `create_param_space()`（5 阶段超参空间）只被独立脚本 `run_optimize.py`（离线优化器）调用，**回测/调仓主流程从不调用**（grep 实证：strategy.py 无任何 optuna/run_optimize 引用）；
3. **所谓"超参多样性"是硬编码，不是选择**：`_train_cv_fold_ensemble`（L2413-2416）`depth_list=[6,6,7,7,8]`、`ss_list`、`cs_list`、`metric_list` 是写死的组合，用于**集成加权**（AUC 加权投票），**没有任何"按验证性能选择最优超参"的步骤**；
4. 唯一自适应机制：early stopping（XGB_EARLY_STOPPING_ROUNDS=20）只调迭代轮数，不调结构/正则参数。

**为什么这是"两层"结构下最根本的问题**：嵌套 CV 的全部价值在于——内层循环（特征 + 超参选择）在训练子集上完成、外层验证块只评分。当前内层只有特征粗筛、超参完全固定，等于**砍掉了内层循环的一半**，且使"选出来的模型"并非"数据选出来的"，而是"人拍脑袋定死的"。超参与特征、样本量（240 天窗口、~28.7K 样本/折）不匹配时，无论外层评估多严谨，都是在评估一个未优化的模型。

### 3.3 核心问题②：OOS MDA 在验证块上计算（选择偏倚，第一版已指出，仍成立）

```python
# ensemble.py _purged_kfold_cv (L1997)
fold_mda, fold_mda_std = compute_mda_oos(model, val_set[fold_feats], y_va, ...)  # ← 验证块!
# 之后 aggregate_fold_votes 用 fold_mda 做跨折准入 (≥vote_min_folds 折 t 检验) → 决定最终特征集
```

**问题**：最终特征集的准入依据 = **验证块上的置换重要性**。验证集以"跨折投票"的隐蔽形式参与了特征选择 → **违反嵌套 CV 的"测试集从未用于特征选择"原则**（Cawley-Talbot 2010: 非嵌套 CV 的验证分数系统性乐观，候选特征越多偏倚越严重——本策略候选上百，偏倚风险大）。

**机制后果**：折内 IC/PSI 是干净的，但 MDA 的置换重要性、t 检验准入都在验证块上完成 → 最终特征部分"看验证集答案"选出 → **meta_auc（五折验证块 AUC 均值）存在乐观偏倚**——而 meta_auc 恰好被用作 AUC 门控（见 3.4），形成"自己选特征、自己打分、自己门控"的闭环偏倚。

**流派辨析（客观）**：项目选择的是"OOS 重要性派"（Prado AFML §8.3：重要性就在 OOS 上评估，据此选特征是"模型内防伪"设计——因子在训练集有效但在未来失效恰恰该剔除）。这与"严格嵌套派"（Cawley-Talbot）不可调和。**不是错误，但用"meta_auc 无偏"的口径去解读时存在偏倚**——需至少注明。

### 3.4 核心问题③：meta_auc 性能门控用途错配（第一版已指出，仍成立）

**事实**：`AUC 门控`（strategy.py L3183-3190）用 `meta_auc`（PKF 五折验证块 AUC 均值）作为放行/降仓/空仓的依据，阈值 0.52。

**论证**：Prado AFML §7.4 的 Purged K-Fold **官方用途是特征重要性/调参评估**（B 用途），不是最终性能报告（A 用途）。原因：
- PKF 训练集**包含验证块之后的未来块**（Fold 2 的 train 含 B4）——"用未来块训练预测过去块"，即使标签被 purge 隔离，未来块的市场状态（牛/熊/波动）通过**时间伪相关**污染评估；
- 这不是模拟实盘部署条件（实盘站在 T 时点，数据只有 ≤T）；
- **性能数字必须用 walk-forward（训练严格早于验证）报告**——expanding 或滚动窗口，特征窗口与验证标签天然无重叠，实盘模拟最真实。

### 3.5 特征回看窗口二阶泄漏（embargo 不防，第一版已指出，仍成立）

Fold 2 示例（240 天，5 块各 48 天，验证块 B1=[48,95]，purge 后训练集=[0,26]∪[116,239]）：

```
验证块 B1 的标签窗口:   [96, 115]      ← 验证标签的"答案"价格区间
训练样本 T=116 的特征窗口: [96, 116]   ← 动量/FFD 特征回看 → 覆盖 [96,115]!
```

- 样本/标签级无泄漏（purge 精确覆盖）；但**特征价格级存在二阶重叠**——训练样本的特征（价格）集合包含验证标签计算所用的价格；
- 这是 purged CV 的**通用边界**（Prado 原版、sklearn 实践都不防），业界实践普遍接受，但严格标准下存在；严重度远低于"验证样本进训练集"。

### 3.6 跨折投票细节（第二版修正：IC 准入层 = cv_feature_consensus）

**投票链路代码实证**（`aggregate_fold_votes`，ensemble.py L864-1030）：

```
L928-934:  IC共识预筛选: normal_feats = consensus_features   ← 决定"MDA投票池"成员
L951:       mda_votes = {f: 0 for f in normal_feats}
L964-979:   每折: mda_mean > t_crit×SE → mda_votes[f] += 1    ← 折内t检验(α=0.05, n_repeats=20)
L1004-1010: candidate_feats = [f for f in normal_feats if mda_votes[f] >= vote_min_folds]
            ← ★真正的准入门槛: vote_min_folds=3
L1022-1025: 候选<vote_min_features(5) → fallback 纯IC排序
L1029-1030: Top-K(40) 截断
```

**用户纠错确认（逐行核实）：**

1. **`cv_feature_consensus=1` 就是 IC 准入层**。config L45 注释原文："IC共识阈值: 特征需出现在≥1/5折中才进入MDA投票池"。代码 L928-934：MDA 投票池（`normal_feats`）**就是** IC 共识特征集（`consensus_features`）。`consensus_features` 由 `_purged_kfold_cv` L2025-2026 生成：`feature_counts[f] >= consensus_n`（=1 → 任一折 IC 筛出即入选）→ **并集，无过滤作用**。

2. **该机制对当前目标确实多余**：
   - **形同虚设**：=1 时是并集，任何一折通过的都进投票池，实际上没有"共识"约束（共识语义需要 ≥2 折才成立）；
   - **方向性错误**：它把"IC 准入"当作 MDA 投票池的门槛——而 IC（线性秩相关）对 XGBoost 这类非线性模型的选特征价值有限（config `weight_ic: 0.0` 注释已明确"XGB非线性模型不考虑线性IC"）。用户不希望 IC 筛掉过多特征，与 `min_feat_ic: 0.001`（极宽松，仅除纯噪声）的现状一致；
   - **真正的准入就是 MDA 投票**：`vote_min_folds: 3`（≥3 折 t 检验通过）——模型内、与模型一致、跨折共识语义正确的精筛门槛。

3. **第一版 P1-1（建议共识 1→2~3）撤回**：该建议建立在"共识阈值提高=更稳健"的错误前提上。用户立场正确——正确方向不是"把 IC 准入调严"，而是**让 IC 退出准入角色**：MDA 投票池 = 通过基础清理（低方差/缺失率/PSI/极宽松 IC=0.001）的全部特征，准入完全交给 MDA 投票。实现上，`aggregate_fold_votes` 已内置向后兼容分支（L935-936：`consensus_features=None → normal_feats = 全部特征`），改造成本极低。

**其余保留判断**：
- Top-K=40、聚类去冗余：业界标准（特征子集 + 相关性代表）✓；
- t 检验准入（n_repeats=20, t_crit 单尾）：样本量 20 次重复，p 值分辨率可接受 ✓；
- `fallback_to_ic_only: true`（候选<5 时降级纯 IC 排序）：降级保护合理，但注意它是 IC 干涉的残留点（仅极端时触发）。

## 六、审查结论（第二版）

1. **三件套是否多余？** —— **在当前多筛层架构下，功能上多余、机制上部分有害**。粗筛职能已被 PKF 内部的"低方差 + 极宽松 IC(0.001) + PSI"完全覆盖（且更规范）；SHAP 探针 0 票空转（结构性失效）、ADV 恒 5 票冗余、CIC 实证 86% 误杀且机制与树模型冲突（已禁用）。**建议整体精简：保留诊断输出，移除投票剔除环节。**
2. **是否"二层 K-Fold"？** —— **不是**。当前是**单层 Purged K-Fold 双用途**（同一批折划分既做特征选择又做性能评估/门控），未实现真正嵌套 CV；注释中的"嵌套"名不副实。
3. **最大的问题是什么？** —— **缺少超参数选择机制**（内层循环缺失，用户指正）：回测主流程无任何超参搜索（optuna 只挂在离线 run_optimize.py），`_train_cv_fold_ensemble` 的 depth_list 是硬编码集成多样性而非选择。其次才是 OOS MDA 计算位置（验证集参与特征选择）与 meta_auc 门控用途错配（性能应 walk-forward）。
4. **IC 准入层（cv_feature_consensus）是否多余？** —— **用户判定成立，确认多余**：=1 即并集（无共识语义），且线性 IC 不应决定非线性模型的 MDA 投票池成员；**真正的准入/共识是 vote_min_folds=3（MDA 投票 t 检验跨折准入）**。建议按 P1-1 移除该层。
5. **值得保留的**：purge/embargo、折内 IC/PSI 零接触、MDA 投票准入（vote_min_folds=3）、t 检验跨折投票、Top-K+聚类、生产全量重训。
